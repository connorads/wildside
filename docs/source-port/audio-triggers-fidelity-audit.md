# Audio Trigger Fidelity Audit

Adversarially-verified per-unit audit of the Kid Chameleon source-port audio-trigger subsystem. The numeric SFX/BGM id mapping is faithful (every live `sound_id()` literal and string-label constant matches `constants.asm`, duplicates and the NO-SOUND `$4E` label included), so the dominant failure pattern is not wrong ids but unwired triggers: ASM-faithful pure helpers exist, carry `#[cfg_attr(not(test), allow(dead_code))]`, expose `sound_effect_label`/`played_sound_effect` `&'static str` fields, and are referenced only from `#[test]` code, while the live frame step pushes nothing into `played_sound_effects`. There is no general `label -> id` conversion (`trace.rs:6404` builds `played_sound_effect_ids` solely by mapping the `played_sound_effects` queue through `sound_id()`), so a decorative label is silence. The hybrid native-player layer (`gems_event_sound_ids`) masks the bulk of this by re-deriving common cues from trace deltas (jump, stomp-via-score, ouch-via-hitpoints, block-hit, etc.), but per-trigger events with no observable delta (Tar Monster emerge/shoot, clock/ankh/evanescent prize cues, the MurderWall BGM override) fall through every heuristic and are genuinely absent. The single behavioural deviation that is not mere silence is the stomp SFX, emitted from an invented `score >= prev + 1000` heuristic that never fires on a real (point-less) stomp.
