# Helmet / Form / Diamond-Power Fidelity Audit

> First committed 2026-05-31; last substantive update 2026-06-23.

Adversarially-verified audit of the Kid Chameleon source-port's **helmet, form, and Diamond-Power** subsystem (`helmets.rs`, with `combat.rs` transform/HP, `projectiles.rs` weapons, `constants.rs`), comparing the live path to the `kid.asm` `Kid_Transform`, `DiamondPower_*`, and per-form weapon routines. Form *movement physics* is covered by `movement-fidelity-audit.md`; this audit covers transforms, abilities, and weapons.

The recurring failure mode is the same one the other audits found crate-wide: **ASM-faithful pure helpers exist and are unit-tested, but carry `#[cfg_attr(not(test), allow(dead_code))]` (or `#[cfg(test)]`) and are never called from the live path.** The Diamond-Power subsystem is the worst-hit area in the whole codebase by this measure — almost every per-power ROM routine is modelled and tested, yet the runtime ignores all of it in favour of flat timers, enum matches, and screen-wide approximations.

Findings that stand out:

- **Architectural — the Diamond-Power shared list, raw payload slots, and sprite compiler are now mirrored at runtime.** The ROM allocates `$FFFFF2AC` slot objects threaded through free/active/last lists, advances each per-frame via the `DiamondPower_Main_Index` jump table, and tears them down on a status word (`kid.asm:44233-44441`). Native now mirrors the shared free/active/last list, raw payload words/longwords by ROM offset, `Diamond_power_active`/shared flag clears, direct sprite link bytes, and the buffered `DiamondPower_CompileSprites sub_3F798` pass.

- **Circle of Doom and Wall of Death still have geometry/collision gaps.** Circle now keeps its ROM slot-owned lifetime and Wall has live sweep slots, but native damage still does not fully mirror the ROM's per-DP-object collision path. The remaining risk is enemy damage being too broad or mistimed compared with the orbit/wall objects in `DiamondPower_Main_CircleOfDoom` / `DiamondPower_Main_WallOfDeath`.

- **Snake Diamond Powers still have architectural gaps.** Native now keeps the six DP-object slots and distinct Mini/Swift/Death Snake parameters, but the wider ROM chain fidelity work is not complete: nearest-enemy acquisition and per-segment collision/sprite ownership still need parity verification against `DiamondPower_Main_Snake` (`kid.asm:44621-44892`).

- **The Eyeclops beam gameplay path now uses state-owned strip collision** rather than a travelling point projectile. Short-beam `off_E560` table dispatch now covers all four ROM tables, and the hard-beam path now exposes the ROM companion object geometry from `loc_E948`.

- **Maniaxe correctness issues are mostly closed:** the thrown axe now has no generic DBF lifetime, survives until enemy/solid/camera cull, uses the solid-only `$6000` terrain delete gate, preserves `x_vel` when `loc_8A74` flips direction bytes, and advances its `stru_8B86` animation clock for spinning native-player art. Remaining Maniaxe rows below are timing/architecture nits, not the former disappearing/static/green-dot failures.

- **ExtraHitPoint Diamond Power is live for the ROM reward orbit/cap path:** native now seeds the ten `DiamondPower_Main_ExtraHPLife` slots and awards HP only on `loc_3FC2A` convergence, incrementing `Extra_hitpoint_slots` while respecting the `< 4` cap.

The transform/HP core (`Kid_Transform`, `sub_7EB2`) is, by contrast, well-wired — its remaining gaps are mostly audio (transform SFX, music-speed) and benign hygiene where `helmet.reset()` is a superset of the ROM's per-flag clear.

## Confirmed gaps

### High severity

**RESOLVED candidate 2026-06-19 — ExtraHitPoint Diamond Power awards through the `loc_3FC2A` slot convergence path and honours the four-slot cap** (`DiamondPower_Main_ExtraHPLife / loc_3FC2A…loc_3FC52`, `DiamondPower_Init_ExtraHitPoint`)
The ROM awards the IronKnight tier-2 +HP only when a converging slot lands, and only if `Extra_hitpoint_slots < 4`: `cmpi.w #4 … bge; addq.w #1,(Extra_hitpoint_slots); addq.w #1,(Number_Hitpoints)` (`kid.asm:44965-44968`). Native now seeds the ten orbiting reward slots from `DiamondPower_Init_ExtraHitPoint loc_3FB90/loc_3FB96`, renders them through `DiamondPower_Main_ExtraHPLife loc_3FBE4`, and only mutates `extra_hitpoint_slots`/`number_hitpoints` on convergence while respecting the ROM cap. Covered by `extra_hit_point_activation_waits_for_orbit_convergence_loc_3fb96_loc_3fc2a`, `extra_hit_point_activation_respects_four_slot_cap_loc_3fc4c`, and the pure `diamond_power_main_extra_hp_life_*` tests.

**RESOLVED 2026-06-23 — Diamond Power shared object list and raw payload slot storage are mirrored at runtime** (`sub_3F586/3F596/3F5BC/3F5E8/3F63C`)
The ROM threads each spawned DP object through the `$FFFFF2AC` slot pool with free/active/last lists, self-removal on status word `$38`, and `Diamond_power_active` maintenance that clears `FiveWayShotReady`/`SamuraiHazeActive`/`KidIsInvulnerable` when the list empties (`kid.asm:44233-44315`). Native now keeps `DiamondPowerObjectListsSub3F5E8` and `DiamondPowerObjectRamSub3F596` on `NativeRuntime`, seeds the ten-slot free list on activation, writes payload fields by raw ROM offsets, walks active-list order for Circle/Wall/Five-Way/Snake/Rain/Extra HP-Life/Invulnerability-Haze, removes slots through the `sub_3F5E8` mirror, and runs the `sub_3F63C` reset mirror without erasing stale slot payload. Covered by `circle_of_doom_activation_seeds_shared_dp_object_list_sub_3f596_3f5bc`, `circle_of_doom_status_removal_updates_shared_dp_object_list_sub_3f5e8`, `invulnerability_expiry_resets_shared_dp_object_list_sub_3f63c`, active-order `diamond_power_five_way_spawns_startup_spread_loc_400de`, and the existing pure `diamond_power_object_*` tests.

**FIXED CANDIDATE 2026-06-20 — Diamond Power per-frame dispatch now keys off `Diamond_power_ID`** (`loc_3F71E`, `off_3F748`, `DiamondPower_Run`)
Every frame the ROM indexes the 20-entry `DiamondPower_Main_Index` jump table by `Diamond_power_ID` and runs the per-power worker (`kid.asm:44331-44416`). Native now stores the ROM ID on activation, including Juggernaut's `DiamondPower_Init_FiveWayShot` ID 5 path, and derives the active worker from the ID instead of only from the collapsed native effect enum. This preserves aliased workers such as TheKid/Skycutter tier-2 Death Snake IDs 10/11 and Tracking Rain ID 12. Covered by `diamond_power_check_stores_rom_id_before_init_loc_3f6b0` and `diamond_power_main_execute_dispatches_rain_from_id_loc_3f71e`. Remaining object-list iteration debt stays with the shared DP linked-list/free-list row above.

**FIXED CANDIDATE 2026-06-20 — Circle of Doom live path no longer uses the invented kill-all AoE** (`DiamondPower_Main_CircleOfDoom loc_3F818`, `DiamondPower_Init_CircleOfDoom loc_3F7D0`)
The ROM spawns 8 slots on a polar orbit (angle step `$200000`, radius `$00210000` shrinking `-$400`/frame, angle `-4`/frame), picks a sprite size from `byte_3F8B4`, and damages enemies via the orbiting **objects'** collision — no kill-all; the power ends when all 8 radii deplete (no timer) (`kid.asm:44469-44558`). Covered by `circle_of_doom_activation_exposes_live_dp_sprites_loc_3f7d0_loc_3f880`, `circle_of_doom_activation_uses_slot_lifetime_not_timer_loc_3f7d0`, `circle_of_doom_main_does_not_blanket_delete_enemies_loc_3f81a_loc_1d84`, `circle_of_doom_slot_collision_refreshes_roster_loc_3f81a_loc_1d84`, and `circle_of_doom_slot_collision_routes_tank_child_through_loc_3b41c`.

**FIXED CANDIDATE 2026-06-20 — Wall of Death live path no longer uses the invented kill-all AoE** (`DiamondPower_Main_WallOfDeath loc_4001E`, `DiamondPower_Init_WallOfDeath loc_3FFE4`)
The ROM spawns 10 slots forming a vertical wall that sweeps right (`+8`) to `x≥$139` then left (`-8`) to `x≤7` while `Diamond_power_timer=$4B0` counts down, then fades by decrementing size every 8th frame, damaging via the swept **objects** (`kid.asm:45368-45458`). **FIXED CANDIDATE 2026-06-20 — Snake Diamond Power no longer grants ad hoc Kid invulnerability** (`DiamondPower_Init_Snake loc_3F91C`, `DiamondPower_Main_Snake loc_3F9A2`)
The ROM spawns a 6-slot chain, each with a 3-entry trail buffer; each frame it propagates the trail, finds the nearest on-screen enemy by Manhattan distance (falling back to Kid), steers the head's angle toward the target octant with per-form turn-rate, moves by `sub_40236` sin/cos plus half of Kid's velocity, and compiles a sprite per segment (`kid.asm:44621-44892`). Native now uses dedicated `diamond_power_snake_slots` with the variant speed/size tables, trail update, target scan, steering, head movement, sprite snapshots, ROM timer durations, signed negative fade/removal, and DP-slot collision queueing through `sub_1D84`/`loc_1EA0`. The remaining concrete bug in this row was the stand-in `progression.invulnerable_frames.max(1)` refresh: `DiamondPower_Main_Snake` never writes `KidIsInvulnerable`, and the native damage-flash countdown should not be refreshed by Snake/Circle/Wall destructive powers. Covered by `destructive_diamond_powers_do_not_refresh_kid_invulnerability_loc_3f81a_40026_3f9a2`, `diamond_power_snake_*`, and the Circle/Wall slot-collision tests. Remaining architectural debt stays with the generic shared DP-object linked-list row and exact render-buffer compile work.

**RESOLVED — Swift Mini-Snake (Micromax T2) uses its distinct ROM parameters** (`DiamondPower_Init_SwiftMiniSnake loc_3F8D0`, `InitData_SwiftMiniSnake`)
The ROM gives Micromax tier-2 the SwiftMiniSnake init (wander `$10`, speed `$480`, size table `5,4,3,2,1,1`), distinct from DeathSnake (wander 6, speed `$400`, sizes `6,6,5,4,3,2`) (`kid.asm:44590-44652`). **FIXED CANDIDATE 2026-06-20 — Five-Way Shot live path uses the ROM slot helpers** (`DiamondPower_Init_FiveWayShot loc_400DE/400F4`, `DiamondPower_Main_FiveWayShot loc_4014C`)
The ROM spawns 5 slots with **screen-relative** positions and **integer screen-pixel** velocities (6/7/8 px/frame from `word_40124`), advancing and **bouncing them off the screen edges**, then shrinking size every 8 frames once the timer goes negative (`kid.asm:45461-45564`). Covered by `diamond_power_five_way_spawns_startup_spread_loc_400de`, `diamond_power_five_way_mirrors_left_facing_spread_loc_400de`, `diamond_power_five_way_bypasses_generic_projectile_cap_loc_400f4`, `diamond_power_five_way_does_not_respawn_after_startup_loc_40140`, and `diamond_power_five_way_survives_zero_timer_and_fades_negative_loc_4019a`.

**FIXED CANDIDATE 2026-06-20 — Eyeclops live beam uses a ROM-style growing strip instead of a point projectile** (`sub_E49A / loc_E4B2 / loc_E70A`, `kid.asm:17999-18480`)

Covered by `eyeclops_beam_strip_hits_multiple_enemies_without_projectile_carrier_loc_e70a`, `eyeclops_beam_short_tables_all_dispatch_from_off_e560_loc_e512_e51a`, `eyeclops_normal_beam_survives_all_short_table_frames_loc_e512_e70a`, `eyeclops_hard_beam_runtime_commits_companion_object_loc_e948`, the C-press/latch tests, and boundary expiry tests.

### Medium severity

**FIXED CANDIDATE 2026-06-20 — Juggernaut 5-way arming uses persistent `FiveWayShotReady`** (`sub_7428`, `DiamondPower_Run Juggernaut branch`, `DiamondPower_Init_FiveWayShot`)
In the ROM the 5-way is a two-stage handshake: `sub_7428` sets the persistent `FiveWayShotReady` byte only from specific player-update states (and only Juggernaut+Start+A+≥5 diamonds); the cost is paid later in init, reached only when the flag is set, and a Juggernaut without the flag is entirely excluded from the Start+A/20-diamond path (`kid.asm:7569-7582,44333-44338,45461-45464`). Native now stores `five_way_shot_ready`, arms it from the raw-`Ctrl_Held` `sub_7428` call site after `DiamondPower_Run`, consumes it from the Juggernaut branch without rechecking Start+A, and clears it with the DP reset/list-clear tails. Covered by `diamond_power_run_juggernaut_requires_five_way_ready_latch_loc_3f71e`, `diamond_power_run_juggernaut_consumes_ready_latch_without_held_input_loc_3f71e`, `diamond_power_juggernaut_costs_5_diamonds`, and `juggernaut_five_way_shot_ready_sub_7428_requires_start_a_and_five_diamonds`.

**FIXED CANDIDATE 2026-06-20 — Circle/Wall diamond objects are spawned, rendered, and used for per-slot contact** (`DiamondPower_CompileSprites loc_3F798`, `loc_3F880 / loc_4009C`)
Both powers compile their slots into the sprite buffer each frame and rely on those objects existing as collision entities (`kid.asm:44441,44538-44553,45446-45453`). Native now stores Circle and Wall slot lists on `NativeRuntime`, initialises them on activation, emits the compiled `word_4020E` sprite snapshots on the next main pass, and routes contact through the DP-slot collision helpers instead of a blanket enemy delete. Covered by the Circle/Wall activation, no-blanket-delete, and per-slot collision tests listed above. Remaining exact shared-pool/list-head fidelity is tracked by the generic DP-object linked-list row.

**FIXED CANDIDATE 2026-06-20 — Snake live path uses the ROM slot chain lifetime, not invented projectiles** (`DiamondPower_Main_Snake`, `loc_3FB20`)
The ROM snake fires no discrete projectiles — it maintains a persistent 6-segment chain whose lifetime equals `Diamond_power_timer` (`$1E0` Mini / `$4B0` Death/Swift), then prunes slots only while the signed timer is negative and `(Time_Frames)&$F==0` (`kid.asm:44850-44856`). Native now keeps snake powers in `diamond_power_snake_slots`, leaves generic projectiles unused, preserves the ROM timer durations, keeps the chain alive at timer zero, and lets negative timer frames shrink/remove slots through `diamond_power_snake_slot_sprite`. Covered by `diamond_power_snake_survives_zero_timer_and_fades_negative_loc_3fb20`, `diamond_power_snake_clears_after_last_negative_fade_slot_loc_3fb20_sub_3f5e8`, `diamond_power_snake_bypasses_generic_projectile_cap_loc_3f92a`, and the snake init/main helper tests.

**Five-Way Shot — projectile lifecycle (timer-gated size shrink + removal) omitted from live path** (`DiamondPower_Main_FiveWayShot loc_4019A`)
FIXED CANDIDATE 2026-06-20: once `Diamond_power_timer` (init `$50`=80) passes zero, the ROM decrements each slot's size every 8 frames and removes it on underflow (`kid.asm:45556-45564`). Native `step_diamond_power` now keeps Five-Way Shot active while its slot list exists, lets the shared timer word wrap through signed negative values, and lets `DiamondPower_Main_FiveWayShot loc_4019A` shrink/remove the live slots instead of the generic zero-timer clear deleting them. Covered by `diamond_power_five_way_survives_zero_timer_and_fades_negative_loc_4019a`.

**FIXED CANDIDATE 2026-06-20 — Eyeclops hard-beam 2-diamond cost follows the ROM render-time gate** (`loc_7606`, `sub_E49A loc_E4B2/loc_E7AC`)
In the ROM the standing/walking handlers only **arm** the hard beam (`$8001 → $FFFFFAB8`) without spending diamonds; the 2-diamond deduction happens at render time inside `sub_E49A` once the decremented beam counter reaches the width-0 point (`loc_E7AC`, `kid.asm:18483-18496`). Native now leaves diamonds untouched on the Start+A arm edge, derives the rendered counter through `eyeclops_beam_render_setup_loc_E4B2`, and applies `eyeclops_hard_beam_gate_loc_E7AC` so the spend happens when `$8001` decrements to `$8000`. The same live step now commits the `loc_E948` hard-beam companion object snapshot. Covered by `eyeclops_hard_beam_loc_e7ac_spends_after_arm_counter_decrements`, `eyeclops_hard_beam_runtime_commits_companion_object_loc_e948`, plus the existing `loc_E7AC_masks_hard_beam_counter_and_allocates_only_at_zero_width`.

**RESOLVED — Maniaxe axe has no generic lifetime cap** (`ManiaxeAxe_Init / loc_8A52`, `kid.asm:9868-9911`)
The ROM flight loop is unbounded: the axe only dies on a solid block, leaving the camera box, or hitting an enemy, and the turnaround counter resets perpetually so the boomerang oscillates while on screen. Native `ManiaxeAxe` now spawns with `lifetime = 0`, is exempt from generic zero-lifetime deletion/decrement, and is culled by the Maniaxe-specific camera/solid/enemy paths. Covered by `maniaxe_axe_spawn_has_no_generic_lifetime_loc_8a52`, `maniaxe_axe_zero_lifetime_survives_inside_camera_bounds_loc_8a52`, and the focused `maniaxe_axe` test group.

The ROM tests `andi.w #$7000,d7; cmpi.w #$6000,d7; beq` — only collision nibble 6 (fully solid) deletes the axe; slope/other tiles let it pass. Native now special-cases `EnemyProjectileKind::ManiaxeAxe` in the terrain contact path so `$4000/$5000` slopes survive and `$6000` solid deletes. Covered by `maniaxe_axe_slope_contact_survives_loc_8a84` and `maniaxe_axe_solid_contact_deletes_loc_8acc`.

**RESOLVED — Maniaxe axe turnaround targets the live axe object, not `projectiles.last_mut()`** (`loc_8A74`, `kid.asm:9879`)

**RESOLVED — Red Stealth airborne down-slash uses the dynamic jump-launch velocity** (`loc_A466` / `loc_B334 / loc_B350 / loc_B380`, `kid.asm:13965-13973`, `kid.asm:14208-14248`)

### Low severity

**Form change — slope-bypass `loc_7AD6` reconstructed from slope-cell probe rather than `Character_Movement==6`** (`loc_7AD6`, `kid.asm:8186`)
The ROM skips the `sub_7B30` fit-check entirely when `Character_Movement == 6` (slope state). Native has no movement-state word; `slope_transform_bypass_loc_7ad6` (`lib.rs:2408`) reconstructs the condition via a floor-probe heuristic (`on_ground && x_velocity!=0 && slope cell`), which can diverge at slope edges where the ROM's state and the probe disagree.

**REJECTED — Form change `+1` cleanup-frame claim is stale; native needs the extra countdown frame** (`loc_7D0A / loc_7E14 / loc_7E90`)
Native sets `form_change_flash_frames = old_frames + new_frames + 1` (`combat.rs:11072`). The raw table loops hibernate exactly the summed `mode` bytes, but native resolves `Kid_Transform` as a frame-end state transition rather than as the ROM's object coroutine. Removing the `+1` made native leave the transform window one frame early: `verify-slice-fast` regressed `any-percent-published` at frame 1130, with oracle still reporting `currently_transforming=true` at frame 1129 and Kid velocity/movement still hibernated at frame 1130. Keep the `+1` unless the native coroutine ordering is redesigned with oracle parity.

**Transform HP — `$FFFFFA64` skip is call-site-implicit, not a modelled guard** (`sub_7EB2`, dying-flag gate `kid.asm:8382-8383`, `loc_B7EA`, `lose_life`)
The ROM gates `sub_7EB2` behind the `$FFFFFA64` dying flag, so the death helmet-strip transform skips the HP reset (HP set to 2 by `lose_life`). Native `transform_hitpoints_sub_7eb2` (`combat.rs:117-121`) is unconditional but only reached via the normal prize-pickup path; the death path uses `enter_death_hidden_state` (`combat.rs:9095-9104`) which sets HP directly. No divergence today, but the skip relies on call-site routing rather than the explicit gate.

**`sub_DB22` — faithful clear helper is `#[cfg(test)]`-gated; live path uses `helmet.reset()` (broader, acceptable)** (`sub_DB22`, `kid.asm:17170`)
`Kid_Transform` calls `sub_DB22` to clear a specific set of transient flags. The faithful `clear_special_movement_state_sub_DB22` (`helmets.rs:4220`) is `#[cfg(test)]` and never compiled into the runtime; the live path calls `self.helmet.reset()` (`combat.rs:8497`) = full `HelmetState::default()`, a superset. Benign, but the dead helper is the canonical failure-mode shape.

**Transform SFX — per-helmet transform sound (`unk_7ED8`), `sfx_Replenish_Health`, and `sfx_Voice_bummer` now core-queued** (`unk_7ED8`, `loc_7E14/loc_7E40`, `loc_7C76`)
