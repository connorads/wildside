# Combat & Collision-Routing Fidelity Audit

Adversarially-verified audit of the Kid Chameleon source-port combat and collision-routing domain. The dominant failure pattern mirrors the enemy audit: the ROM's single unified `GfxObjects_CollisionKid` mechanism derives per-sprite-frame hitboxes from `CollisionSize_Index`, writes a directional `colid` word into *both* the Kid and the enemy collision slots, and dispatches every outcome (stomp, side-plough, hurt, crush) through one `off_B640` jump table — whereas the native port substitutes invented fixed-extent boxes, collapses the directional `colid` to a Stomp/Damage/None trichotomy, delivers side/below words to almost no enemy, and routes the authoritative murder-wall crush and the Berzerker reflect through bespoke per-case paths keyed off the wrong data. Faithful verbatim helpers for the ROM mechanism (`sub_21F8`, the `sub_1D76`/`sub_1D84` sweep, the `loc_1D00` invuln gate, the `sub_226A` shooter-block path) consistently exist and are unit-tested but carry `#[cfg_attr(not(test), allow(dead_code))]` and are never wired into the live frame step. The most severe consequences are concentrated in three places: the generic 8×16 enemy contact box used for every non-special family, the murder-wall crush that does single-HP damage instead of an instant kill, and the Berzerker side-reflect keyed to the wrong `object_meta` bit.

## Confirmed gaps

### High severity

**Enemy contact box is a fixed 8×16 for all families instead of per-frame `CollisionSize_Index` subboxes** (`GfxObjects_CollisionKid / GfxObjects_CollisionKid_SubBoxLoop / GfxObjects_CollisionKid_SubBoxLoop_Flipped / loc_171C`)
The ROM derives each enemy's hitbox per sprite-frame: it reads the object's `$22` mapping pointer, halves it, indexes `CollisionSize_Index` to a NUL-terminated list of 8-byte L/W/T/H subboxes (`kid.asm:3327-3331`), and loops over every subbox for the active frame (unflipped `3336-3353`, flipped `3356-3374`). The live native path `classify_enemy_contact_with_half_width` → `enemy_contact_bounds` instead returns a single fixed box — a generic 8×16 (`ENEMY_CONTACT_HALF_WIDTH=4`, `ENEMY_CONTACT_HALF_HEIGHT=8`, `constants.rs:379-384`) for every family except three hardcoded static boxes (Dragon `0x0D`, Tank mouth/turret `0x0A`/`0x0B`, MiniHoppingSkull `0x1C`). It never indexes `CollisionSize_Index`, never reads the per-frame mapping, and collapses the multi-subbox loop to one box, so every other family's contact dimensions and per-animation-frame hitbox changes are wrong. `NativeObjectSnapshot` carries no `$22`/frame-index/subbox state, so the live path structurally cannot reach the ROM data. Kind: deviating. Native `crates/kid-core/src/combat.rs:10486`, `crates/kid-core/src/combat.rs:10617`, `crates/kid-core/src/constants.rs:379`.

**Fixed 2026-06-12: `loc_B692` x_vel reflect now follows `object_meta` bit 15 instead of boss bit 7** (`loc_B678 / loc_B692 / return_B690 / loc_3DDEE`)
The ROM `loc_B678` negates Kid x_vel (`loc_B692` `neg.l x_vel`) on a charging-Berzerker side contact only when the contacted enemy's `object_meta` bit 15 is set (`bclr #$F,d6; bne loc_B692`), else returns via `return_B690` with no velocity change. A whole-ROM scan showed the live bug: Scorpion sting/lunge sets bit 15 with `ori.w #$C000,object_meta(a3)` (`Scorpion.asm:193/195`), while every multi-head boss head sets only bit 7 (`bset #7,object_meta`, `kid.asm:42069/42194/42320`). Native now derives the bit-15 carrier from live `Scorpion.scorpion_sting_frames > 0`, skips boss heads, and has regressions for both routes (`berzerker_charge_loc_b692_skips_boss_heads_with_only_object_meta_bit_7`, `berzerker_charge_loc_b692_reflects_player_x_velocity_once_for_scorpion_sting_bit_15`). Kind: fixed. Native `crates/kid-core/src/helmets.rs:4354`, `crates/kid-core/src/tests/projectile_tests.rs:9561`.

**Murder-wall contact does single-HP `apply_damage` instead of `Crushed_to_Death` instant kill** (`sub_5E02 loc_5E34 / Character_CheckCollision / off_B640 / Crushed_to_Death / Death`)
The ROM murder wall writes `collision_type=colid_rightwall(4)` into the Kid GfxObject (`sub_5E02 loc_5E34`: `move.w #4,$38(a0)`, `kid.asm:5860`). `Character_CheckCollision` reads it and dispatches via `off_B640`: index 0 jumps to `Crushed_to_Death` → `moveq #0,d7; bra.w Death`; `Death`/`lose_life` clear `Extra_hitpoint_slots`/`Current_Helmet` and decrement `Number_Lives` with NO HP decrement or survival branch — an unconditional instant kill. The native live path `resolve_frame_hazards` → `murder_wall_kills_player` → `apply_damage` instead subtracts one hitpoint and only kills when `number_hitpoints` reaches 0 while in TheKid form, so a helmeted player, or The Kid with >1 HP, survives a murder-wall crush in native but dies instantly in the ROM. Kind: deviating. Native `crates/kid-core/src/combat.rs:10920`, `crates/kid-core/src/combat.rs:10925`, `crates/kid-core/src/weather.rs:2327`, `crates/kid-core/src/combat.rs:9200`.

**Murder-wall crush is gated on invulnerability frames, but the ROM crush bypasses all invuln checks** (`Character_CheckCollision / off_B640 / Crushed_to_Death`)
The ROM's `Crushed_to_Death` dispatch happens directly from `Character_CheckCollision`'s `off_B640` jump table for `colid_rightwall`, with no invulnerability test — the `Just_received_damage`/invuln checks live only inside `Check_for_recent_damge` (the `colid_hurt`/`colid_kidbelow` entries), not the rightwall entry. So a player flashing post-damage who walks into the murder wall still dies in the ROM. The native `resolve_frame_hazards` gates the murder-wall kill on `invulnerable_frames == 0 && !kid_is_invulnerable`, so a recently-damaged invulnerable player passes through the wall unharmed. Kind: deviating. Native `crates/kid-core/src/combat.rs:10921`, `crates/kid-core/src/combat.rs:10922`.

### Medium severity

**Stomp bounce never applies bit14 deferred contact damage (`bclr #$E,d6`)** (`Jump_On_Enemy / loc_B6DA / Character_CheckCollision / loc_1CF2`)
The ROM stomp tail at `loc_B6DA` ends with `bclr #$E,d6; bne.w Check_for_recent_damge` — bit14 of the stomped object's `object_meta` makes the Kid ALSO take contact damage right after the bounce. `d6` is the full `object_meta` copied to the Kid at `loc_1CF2` (`move.w $3A(a2),$3A(a0)`) and preserved across the bit15/bit14 strip in `Character_CheckCollision` (`kid.asm:14541-14546`); reachable producers exist (Scorpion ORs `$C000` during the sting and gives its stinger gfx-object meta `$4013`, `Scorpion.asm:47/193`). The native stomp path has no equivalent: `NativeObjectSnapshot` carries no `object_meta`, `classify_enemy_contact_with_half_width` returns only Stomp/Damage/None on geometry, and `apply_pending_stomp_bounce` only documents the bit14 step in a comment (`combat.rs:7666-7667`) — moreover the live contact-damage resolver is gated `if !self.stomped_this_frame`, so a stomp already suppresses ALL contact damage that frame with no bit14 exception. So a Kid that stomps a bit14-flagged hurtbox bounces but never takes the extra hit. Kept medium rather than high because the only reachable producer (the Scorpion sting tail) is itself currently unmodelled, leaving the effect latent. Kind: missing. Native `crates/kid-core/src/combat.rs:7655`, `crates/kid-core/src/combat.rs:8414`, `crates/kid-core/src/combat.rs:10583`, `crates/kid-core/src/types.rs:1547`.

**Hostile projectiles are not removed/consumed on Kid contact during i-frames (native skips the overlap test entirely)** (`GfxObjects_CollisionKid_Collide / loc_1c18 / loc_1CF2 / loc_1D00 / Check_for_recent_damge / loc_342D6 / loc_34336`)
In the ROM the gfx-object classifier writes the contact `colid` to BOTH the Kid slot (`$38(a0)`) and the object slot (`$38(a2)`) unconditionally on a fresh overlap (`loc_1CF2`); the invuln logic (`Check_for_recent_damge` gate, and the largely-dead `loc_1D00` `KidIsInvulnerable` clear) only suppresses Kid DAMAGE / clears the Kid's `colid`, never the object's. So a hostile projectile object (an Archer arrow: `loc_342D6` deletes itself whenever `collision_type(a3)!=0` at `loc_34336`) is destroyed on contact even while the Kid is in i-frames. The native live path runs `step_projectiles()` unconditionally but gates `projectile_hits_player` (the only place projectiles are removed on Kid contact) behind `invulnerable_frames == 0 && !kid_is_invulnerable`. While the Kid is invulnerable the overlap test is never called, so the projectile is neither damaging nor removed and can re-hit the moment i-frames expire if it still overlaps. (The refuter noted a global `FA74` short-circuit suppresses the ROM `$38(a2)` write on the frame following any contact, so the ROM deletes only on fresh-overlap frames, narrowing but not eliminating the divergence.) Kind: deviating. Native `crates/kid-core/src/combat.rs:10907`, `crates/kid-core/src/projectiles.rs:3041`, `crates/kid-core/src/projectiles.rs:2377`.
