# Platform Fidelity Audit

Adversarially verified audit of the Kid Chameleon source-port's platform subsystem (`platforms.rs`, with `enemies.rs` platform load/activation, `blocks.rs` lift blocks, `types.rs` field decode), comparing the live path to the `kid.asm` platform routines.

The recurring failure mode is the one the enemy/movement/level-loading audits found crate-wide: ASM-faithful pure helpers exist and are unit-tested, but carry `#[cfg_attr(not(test), allow(dead_code))]` (or are `#[cfg(test)]`-gated) and are never called from the live path. Platforms show this acutely. Almost the entire `Platforms_CheckCollision` escape/carry algorithm, the slot allocator, the sprite-tiling compiler, and the Trap-platform coroutines are modelled helper-for-helper yet dead, while the runtime uses a separate approximation.

Findings that are not simple modelled-but-unwired gaps and deserve human verification before acting:

- Architectural. The ROM's live 17-slot free-list object model is now wired into the platform loader, but native still materialises slots as a Vec. `Initialize_Platforms`/`Allocate_PlatformSlot`/`Deallocate_PlatformSlot` (a linked free-list of 17 `$22`-byte slots at `$FFFFEDBA`, `kid.asm:4166-4251`) now have live loader coverage for reset links, allocation head insertion, active-chain order, deallocation, immediate free-head reuse, and `$20(a3)` loader-offset slot ownership across record wraps. The runtime `ActivePlatform` roster consumes that linked slot order for collision scans, special-platform delete actions now deallocate the linked slot before removing the native object, and `Addr_PlatformStandingOn`/`$FA96` carry Platform_RAM slot addresses. Remaining architectural work is explicit linked-slot nodes/lifetimes for every collision scan and full Platform_RAM identity across all references.

- Current-code spot check, 2026-06-13. The original "two genuine value bugs to verify" are no longer live: placement x/y now route through `platform_layout_coord_fixed_loc_2762` (`types.rs:2263,2277`; `platforms.rs:509-518`), and spawned lift platforms now seed `y_velocity: -0x0001_0000` with ASM-cited regressions (`blocks.rs:3709`; `tests/runtime_tests.rs:11099-11102`; `tests/level_tests.rs:19956-19958`). Treat those rows as superseded by `docs/source-port/fidelity-audit-staleness-2026-06-10.md`.

- Current-code spot check, 2026-06-13. The original "`sub_8ED0` support check hardcodes Kid half-width" claim is also superseded: the live carry caller now passes `current_form.half_width()` and `current_form` (`platforms.rs:711-718`), with `platform_carry_uses_current_form_half_width_loc_8ed0` covering the behaviour.

- Current-code spot check, 2026-06-16. TrapPlatformDown and TrapPlatformUp are no longer entirely inert: `pp=4`/`pp=8` dispatch through native `PlatformSpecialState` variants, the live special-platform step runs their wait/move loops, `ActivePlatform` carries the ROM `$12(a3)` deactivation byte, and delete actions now route through `Deallocate_PlatformSlot` slot-model reuse before object removal.
