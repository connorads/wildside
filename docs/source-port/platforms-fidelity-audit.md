# Platform Fidelity Audit

Adversarially-verified audit of the Kid Chameleon source-port's **platform** subsystem (`platforms.rs`, with `enemies.rs` platform load/activation, `blocks.rs` lift blocks, `types.rs` field decode), comparing the live path to the `kid.asm` platform routines.

The recurring failure mode is the same one the enemy/movement/level-loading audits found crate-wide: **ASM-faithful pure helpers exist and are unit-tested, but carry `#[cfg_attr(not(test), allow(dead_code))]` (or are `#[cfg(test)]`-gated) and are never called from the live path.** Platforms are an acute case — almost the entire `Platforms_CheckCollision` escape/carry algorithm, the slot allocator, the sprite-tiling compiler, and the Trap-platform coroutines are modelled helper-for-helper yet dead, while the runtime uses a separate approximation.

Findings that are **not** simple modelled-but-unwired gaps and deserve human verification before acting:

- **Architectural — the ROM's 17-slot free-list object model is still approximated by a monotonic high-water index plus loaded-record mask.** `Initialize_Platforms`/`Allocate_PlatformSlot`/`Deallocate_PlatformSlot` (a linked free-list of 17 `$22`-byte slots at `$FFFFEDBA`, `kid.asm:4166-4251`) still have no true native counterpart. The live path now caps materialised platforms at 17, tracks loaded records, exposes a capped `number_platforms` trace value, and emits synthetic `$EDBA + index*$22` slot addresses for diagnostics, but it does not model real linked free-list pop/push reuse or exact deallocation order.

- **Current-code spot check, 2026-06-13.** The original "two genuine value bugs to verify" are no longer live: placement x/y now route through `platform_layout_coord_fixed_loc_2762` (`types.rs:2263,2277`; `platforms.rs:509-518`), and spawned lift platforms now seed `y_velocity: -0x0001_0000` with ASM-cited regressions (`blocks.rs:3709`; `tests/runtime_tests.rs:11099-11102`; `tests/level_tests.rs:19956-19958`). Treat those rows as superseded by `docs/source-port/fidelity-audit-staleness-2026-06-10.md`.

- **Current-code spot check, 2026-06-13.** The original "`sub_8ED0` support check hardcodes Kid half-width" claim is also superseded: the live carry caller now passes `current_form.half_width()` and `current_form` (`platforms.rs:711-718`), with `platform_carry_uses_current_form_half_width_loc_8ed0` covering the behaviour.

- **Current-code spot check, 2026-06-16.** TrapPlatformDown and TrapPlatformUp are no longer entirely inert: `pp=4`/`pp=8` dispatch through native `PlatformSpecialState` variants, the live special-platform step runs their wait/move loops, and `ActivePlatform` now carries the ROM `$12(a3)` deactivation byte for loader-driven special-platform deletion. Remaining free-list tail work is the exact `Deallocate_PlatformSlot` object deletion/reuse order.

## Confirmed gaps

### High severity

**Slot pool — free-list replaced by monotonic `next_index`; no allocation model at runtime** (`Initialize_Platforms/sub_231C`, `Allocate_PlatformSlot/sub_238E`, `Deallocate_PlatformSlot/sub_23B4`)
Partially fixed 2026-06-13 for capacity only: the visible roster and live `active_platforms` rebuild now cap active materialisation at the ROM's 17-slot pool size. Regression: `platform_loader_active_roster_loc_23ae_caps_at_17_slots`. Follow-up 2026-06-16: new platform allocations are inserted at the front of the active vector, matching `Allocate_PlatformSlot/sub_238E` writing `Addr_FirstPlatformSlot`; regression: `runtime_platform_roster_allocates_new_slots_at_front_loc_238e`. Follow-up trace work now exposes synthetic Platform_RAM addresses from the `$EDBA + index*$22` pool layout in `native_platform_slots_loc_257e`, so oracle diffs can compare native vector order against ROM linked-slot addresses. The pure `Initialize_Platforms/sub_231C` model now builds that free-list and clears `Addr_FirstPlatformSlot`/`Number_Platforms`/`PlatformLoader_Offset`; regression: `initialize_platform_slots_sub_231c_builds_the_free_list_and_clears_state`. Remaining gap: native still does not run that real linked free-list live, so offset-keyed pop/push and explicit deallocation/reuse order are still approximated by the monotonic high-water cursor.

**Platform loader — range check uses camera-based enemy window + relative buffers instead of Kid position + absolute (byte×32) edges** (`Manage_PlatformLoading/sub_2744, loc_2762`, `kid.asm:4684-4709`)
The ROM loads Kid's X/Y from `Addr_GfxObject_Kid` and range-checks each placement using the buffer **bytes as absolute world edges** scaled by `asl #5` (×32): `bufL×32 > KidX` out-left, etc. Native `platform_is_active` (`platforms.rs:631-649`) instead compares `placement.x/.y` against the **camera** `ActivationWindow` (`enemies.rs:8543-8551`) and treats `buffer_left/right/top/bottom` as small deltas around that window — wrong reference point (camera vs Kid), wrong buffer semantics (relative delta vs absolute ×32 edge), and the ×32 scale is never applied. Load/unload timing diverges.

**Platform loader — placement x/y decode omits `asl #4` (×16), so loaded position is 16× too small** (`Manage_PlatformLoading loc_286E`, `kid.asm:4717-4723`)
The ROM multiplies the layout x/y words by 16 before storing (`asl.w #4,d7`; the `ptfm` words are 16px block units). Native `from_placement` (`types.rs:2085,2099`) and `active_platforms` (`platforms.rs:608-609`) store `x_pos = placement.x << 16` / `y_pos = placement.y << 16` with **no ×16** (`placement.x` is the raw `ptfm` word; `lib.rs:1304`/test `lib.rs:5482` confirm `ptfm 24 → placement.x==24`). Downstream collision reads `x_pos>>16` as pixels (`platforms.rs:811-812`), so platforms land 16× closer to origin. **Highest-impact claim — verify against a running level.**

**Sprite emission/tiling is dead; live renderer draws one fixed frame (no width/height tiling)** (`Make_SpritesFromPlatforms / loc_244C + off_24AC`, `kid.asm:4325-4453`)
The ROM walks the active list, culls each against the 320×224 window using the `$1A/$1C` size words, and dispatches through `off_24AC` into 5 strip routines that emit `(w+1)×(h+1)` 16px cells via `loc_2548`. Faithful ports of all of these exist (`platform_sprite_dispatch_loc_244C` `platforms.rs:997`, `emit_platform_sprite_loc_2548` `1058`, the strip helpers `1094-1222`) but every one is `allow(dead_code)`, test-only. The live renderer `push_platform_tiles` (`crates/kidcli/src/native_player/sprites.rs:1439-1458`) draws a single fixed art frame per platform with no tiling, no culling, no variant dispatch; the snapshot drops `h_variant/v_variant/width_px/height_px` (`platforms.rs:603-607`, `types.rs:1488`). Multi-cell platforms render as one tile.
Partially fixed 2026-06-15: native object snapshots now carry active-platform width/height debug metadata and `push_platform_tiles` emits repeated 16px cells from those dimensions. Remaining gap: exact `off_24AC` variant dispatch, culling, and ROM art-table/render-flag selection are still not live-rendered.
Partially fixed again 2026-06-15: snapshots now also carry the retail `$1F(a3)` render byte and `PlatformArtAddr_Table` word, while `push_platform_tiles` applies `loc_244C` viewport culling and `off_24AC` strip counts for valid variants. Fixed candidate 2026-06-15: the live renderer now selects its two-frame fallback from the `$18(a2)` mapping word rather than the native platform kind. Remaining gap: the live renderer still maps the ROM art words onto the two extracted horizontal/vertical frames rather than drawing the exact mapping-word art sequence.

**`Platforms_CheckCollision` — entire escape-vector/flag algorithm modelled but unwired; live path is a snap-tolerance approximation** (`sub_2574, loc_257E…loc_2672`)
The ROM computes exact AABB overlap of Kid's hitbox vs every platform, derives both horizontal and both vertical escapes, takes absolute values, and pushes Kid out along the **smaller axis** (`kid.asm:4465-4578`). A complete faithful decomposition exists at `platforms.rs:96-382`. Partially fixed 2026-06-13/15/16: the live airborne path now uses the ASM overlap/escape helpers, no longer has the old terrain snap-tolerance fallback, restarts after side and top-support pushes, and builds the airborne AABB from the current form's hitbox dimensions like `loc_2590`. Regressions include `platform_collision_uses_horizontal_escape_when_side_overlap_is_smaller_loc_2686`, `platform_collision_requires_aabb_overlap_not_snap_tolerance_loc_25a0`, and `platform_collision_airborne_aabb_uses_current_form_half_width_loc_2590`. Follow-up trace work exposes native `platform_collision_scratch_loc_257e`, native `native_platform_slots_loc_257e`, and oracle `oracle_platform_slots_loc_257e` for side-by-side slot-order audits. Follow-up 2026-06-16: new allocations now enter the active vector at the scan head like `Addr_FirstPlatformSlot`, and standing-platform indices are remapped after special-platform deletion. Remaining gap: native scan order is still derived from a rebuilt vector and layout identity, not true Platform_RAM linked slot addresses/free-list nodes.

**`Platforms_CheckCollision` — horizontal carry (loc_2686/26B6/26C0) omitted; Kid never pushed/carried sideways** (`loc_2686, loc_26B6, loc_26A2, loc_26C0`)
Partially fixed 2026-06-13: live horizontal side escapes now call the ASM-cited `loc_26A2`/`loc_26B6` helpers and copy only same-direction platform `$A(a2)` velocity into Kid's `x_velocity`, after the existing `loc_2686` position push.
