# Terrain Collision & Physics Fidelity Audit

Adversarially-verified audit of the terrain collision and physics layer of the Kid Chameleon source-port. The probe geometry and tile decode are largely faithful: row/column arithmetic, span endpoints, the half-width tables, the disguised-ghost filter and the slope-nibble mapping all match the ROM. The dominant failure pattern is in the *consumption* of what those probes find. The ROM's shared horizontal cell scan (`sub_914A`/`sub_922C`) walks the whole hitbox span and tags `collision_type=colid_kidbelow` ($28) on any spike cell it crosses; the native floor/wall/ceiling paths collapse each scan to a single selected cell and drop that tag entirely — so a spike above the head deals no damage, a spike masked by a taller solid deals no damage, and floor-spike contact is rewritten as unconditional instant death rather than the ROM's helmet/HP/invuln-gated hit. Alongside this, Lion airborne charge now consumes `sub_36B3C`/`sub_36BD6` body-overlap and lead-column X-stop results plus the `sub_36C6A`/`sub_36CB8` vertical full-span scans, while the down-look camera pan is dead because the look accumulator is capped at exactly the value at which the pan would begin.

**RESOLVED candidate — ceiling spike contact routes through normal `loc_B700` damage** (`loc_91A6 / loc_9188 / sub_914A / Character_CheckCollision / Check_for_recent_damge`)
In `sub_914A`'s upward span scan, a Spikes ($7000) tile in the head-row branches to `loc_91A6`, which writes `collision_type(a3)=colid_kidbelow` ($28) before falling into the stop handler; the next move-state loop's `Character_CheckCollision` reads $28, does `subq.w #4,d7` and indexes `off_B640` entry 9 = `Check_for_recent_damge`. Kind: fixed-candidate, `crates/kid-core/src/movement.rs`, `crates/kid-core/src/combat.rs`, `crates/kid-core/src/tests/level_tests.rs`.

**RESOLVED candidate — spike contact uses the helmet/HP/invuln-gated `loc_B700` path** (`loc_91A6 / loc_92B6 / Character_CheckCollision / off_B640 / Check_for_recent_damge / loc_B700 / loc_B786`)

**Negative-coordinate guard returns Empty instead of reading the padded rows / unsigned-X wrap** (`sub_B55C / loc_331D2 / loc_331F6 / loc_33286`)
`sub_B55C`/`loc_331D2` compute the row via `asr.w #4` (signed) on `y_pos+offset` and the column via `lsr.w #4` (unsigned) on `x_pos+offset`, then index the `$FFFF4A04` row-pointer table, which is allocated with 2 valid rows above the top and 8 below. Native short-circuits `if sample_x < 0 || sample_y < 0 { return 0 }` and clamps cell coords with `.max(0)`, so for a probe 1-2 cells above the level top the ROM reads a real (normally empty) padded row while native returns Empty. In normal play these padded rows are empty so both yield Empty, but the implementations differ at the edge. Kind: deviating, `crates/kid-core/src/terrain.rs:1477` / `:1578` / `:1634`.

**Native adds an extra [0,max_pos] clamp to the camera result not present in ASM `loc_724E`/`loc_72E2`** (`loc_724E / loc_72E2`)
After the per-frame velocity (clamped to ±8), the ASM simply does `add.w d2,(Camera_X_pos)` / `add.w d3,(Camera_Y_pos)` with no clamp of the resulting camera position to the level bounds — it relies on the earlier target clamp plus the ±8 velocity limit. In normal play this is unobservable because the velocity edge branches and ±8 cap keep the camera in range, but it diverges from the spec and could differ in pathological cases (negative `max_pos`, where the ASM unsigned compare differs from native signed `.min()`). The native comment acknowledges the extra clamp. Kind: deviating, `crates/kid-core/src/physics.rs:927`, `movement.rs:7104`.
