# Level-Flow & Timer Fidelity Audit

Adversarially-verified per-unit audit of the Kid Chameleon source-port level-flow, timer, death and end-of-level subsystems. The dominant failure pattern is the codebase-wide "faithful-but-untranslated normalisation": the ROM keeps several state variables in a deliberately pre-compensated form (the `addq #1,(Time_Seconds_low_digit)` + `SubSeconds=1` timer normalisation at level start and at each clock collect; the `clr.w (Extra_hitpoint_slots)` that `lose_life` performs before reseeding HP; the MapOrder reverse/forward index translation), and the native port previously either dropped the compensating step or substituted a structurally simpler model. The timer normalisation, death extra-HP clear, final-level `$33` ending check, and teleporter MapOrder reverse scan are now fixed-candidates with regressions.

## Confirmed gaps

### High severity

**RESOLVED candidate — death respawn clears `Extra_hitpoint_slots` before restoring base HP** (`lose_life` / `Death` / `Init_Timer_and_Bonus_Flags`; reported by units respawn-state-persistence-reset, death-respawn-lifecycle-state-machine and death-cause-routing-and-windup-entry)
The ROM's `lose_life` makes `clr.w (Extra_hitpoint_slots).w` (kid.asm:14764) its very first action, *before* `move.w #2,(Number_Hitpoints).w` (kid.asm:14768), so every same-level death respawn drops the player back to the base TheKid HP cap of 2; the `Death` routine also zeroes the field on entry (kid.asm:14719). Native now clears `progression.extra_hitpoint_slots` in `enter_death_hidden_state` before reseeding `number_hitpoints = PlayerForm::TheKid.max_hitpoints()`, matching the same death/respawn boundary used by the live `lose_life` model. The regression `loc_b7ea_death_strips_helmet_and_resets_to_the_kid` seeds stale DP extra-HP slots before death and proves the post-windup hidden state has form=TheKid, base HP=2, and slots=0. Kind: fixed-candidate. `crates/kid-core/src/combat.rs`, `crates/kid-core/src/tests/level_tests.rs`.

**RESOLVED candidate — final-level ending trigger uses hard-coded `Final_LevelID=$33`** (`loc_D7F4` / `End_Credits` / `Final_LevelID` / `Boss4_LevelID`; reported by units level-complete-to-next-level-exit-routing and final-boss-ending-trigger-and-bonus-entry)
The ROM EOL routine routes the ending with an exact compare: `cmpi.w #Final_LevelID,(Current_LevelID).w; beq.w End_Credits` else `addq.w #1,(Current_LevelID).w; bra.w Teleport` (kid.asm:16912-16917), where `Final_LevelID = $33` (kid.asm:30) `== Boss4_LevelID = $33` (kid.asm:47). `Current_LevelID` is the *logical* MapOrder index, so native now mirrors `loc_D7F4` by treating `LevelId(0x33)` as final regardless of later MapOrder tail entries. Regressions `final_level_id_33_sets_game_complete_on_advance_loc_d7f4` and `map_order_tail_after_final_level_does_not_end_game_loc_d7f4` cover the final-level ending and the non-final tail case. Kind: fixed-candidate. `crates/kid-core/src/level.rs`, `crates/kid-core/src/tests/combat_tests.rs`.

**RESOLVED candidate — teleporter destination uses the `loc_BCD6` MapOrder reverse scan** (`loc_BCB2` / `loc_BCD6` / `loc_BCEA` / `Get_PlatformLayoutAddress`)
The ASM telepad record's high byte at `+6` is a *map number*, not a logical index. `loc_BCB2` extracts it (`move.w (a4),d7; asr.w #8,d7`), then `loc_BCD6` scans `LnkTo_MapOrder_Index` byte-by-byte so that `d6` becomes the *logical index* whose MapOrder entry equals that map number; `loc_BCEA` compares `d6` (the index) to `Current_LevelID` and stores `d6` back. Native now routes teleporter destinations through `teleporter_dest_level_loc_bcd6`, stores the logical MapOrder index in `pending_level_skip`, and preserves same-level inline repositioning when the scan resolves to the current logical level. Regressions `teleporter_cross_level_sets_pending_skip_loc_bcd6` and `live_teleporter_pending_skip_uses_map_order_index_loc_bcd6` cover the non-identity MapOrder case. Kind: fixed-candidate. `crates/kid-core/src/level.rs`, `crates/kid-core/src/combat.rs`, `crates/kid-core/src/blocks.rs`, `crates/kid-core/src/tests/combat_tests.rs`, `crates/kid-core/src/tests/projectile_tests.rs`.

### Medium severity

**RESOLVED candidate — level timer starts with the ROM's 181s pre-decrement budget** (`Init_Timer_and_Bonus_Flags` / `Init_SpriteAttr_HUD` / `loc_BE82`)
On level entry the ROM sets minutes=3/seconds=0 in `Init_Timer_and_Bonus_Flags` (kid.asm:6555-6561), then `Init_SpriteAttr_HUD` does `addq.w #1,(Time_Seconds_low_digit)` (kid.asm:27099) **and** `move.w #1,(Time_SubSeconds)` (27100). The true start state is therefore 3:01 with `SubSeconds=1`; the first gameplay frame drains `SubSeconds 1→0`, reloads `$3C`(60) and decrements 3:01→3:00 (kid.asm:15482-15485). Native now seeds `LevelTimer::new()` at 181 seconds with `sub_frames=1`, preserving the same first-frame normalisation and one-second-longer death budget. The EOL completion-time path deliberately uses a separate `LEVEL_TIMER_COMPLETION_BASE_SECONDS=180` because `loc_C0CC` subtracts remaining time from literal `$B4` and adds `Clocks_collected*$B4`. Kind: fixed-candidate. Native locations: types.rs, constants.rs, combat.rs, trace.rs.

**RESOLVED candidate — clock-bonus now applies the `loc_FF92` `+1`-second carry before `loc_FFDE` adds three minutes** (`loc_FFDE` / `loc_FFFC` / `loc_10002`)
The ROM clock-collect tail, immediately before the `+3`-minute add, does `addq.w #1,(Time_Seconds_low_digit)` with full BCD carry into seconds-high/minutes (kid.asm:21271-21279), then `loc_FFDE` adds 3 to `Time_Minutes` capped at 10:00 (21282-21293), then `loc_FFFC` sets `Time_SubSeconds=1` (21296). Native `add_clock_bonus` now adds `LEVEL_TIMER_CLOCK_COLLECT_SECONDS=181` and caps to 10:00, while the EOL speed-bonus elapsed formula still multiplies `Clocks_collected` by the ROM's flat `$B4`. Regressions cover the clean +3:00 after the compensating tick and the 6:59→10:00 cap boundary. Kind: fixed-candidate. Native locations: types.rs, constants.rs, combat.rs, trace.rs.

**RESOLVED candidate — Continue (CONTINUE?) screen accepts Start only and preserves the second Start window** (`loc_D350` / `loc_D3AA` / `Use_Continue` / `Continue_Screen`)
On the CONTINUE? screen the ROM polls `Ctrl_Held` and branches to `Use_Continue` only when the Start bit is held: `tst.b (Ctrl_Held).w; bmi.s Use_Continue` (kid.asm:16528-16532, identically at 16555-16559); `Button_Start=7` so `tst.b`+`bmi` tests bit 7 alone. Native gates the live `ContinueCountdown` use path on `input.start`, has a regression asserting A/B/C alone leave the countdown running, and includes the post-fade `$EF` `loc_D3AA` Start window before title return. Reachable in normal play via GameOver → ContinueCountdown when `number_continues>0`. Kind: fixed-candidate.

**RESOLVED candidate — GameOver arm no longer injects a 2P player-switch the ASM zero-lives path never performs** (`loc_D052` / `loc_D17E` / `loc_D25E` / `loc_D2CE` / `loc_D3F0` / `Use_Continue`)
When the current player's `Number_Lives` reaches 0 the ROM always takes `beq.w loc_D052` (game-over teardown), even in two-player: `loc_D17E` merely allocates the P1/P2 indicator text objects then falls into the same `loc_D25E` continue/title decision, reaching `loc_D3F0` (`clr.w (Game_Mode)` → title) when no continues remain (kid.asm:16325-16601). The surviving-player handoff (`loc_B894`/`loc_B8D0`/`not.b Current_player`) lives only on the non-zero-lives `Teleport` path. Native now keeps `try_switch_player()` only in the non-zero-lives Dying branch and returns to title from the no-continues GameOver arm even when the other 2P slot has lives. Regressions `loc_d25e_p1_game_over_does_not_force_p2_active` and `two_player_game_over_returns_to_title_even_when_other_has_lives` cover the corrected zero-lives path, while `loc_b8ba_two_player_both_alive_swaps_current_player` preserves the real non-zero-lives turn switch. Kind: fixed-candidate. `crates/kid-core/src/boot.rs`, `crates/kid-core/src/tests/helmet_tests.rs`.

**RESOLVED candidate — FC36-set respawn/continue/cross-level-teleport paths clear both NoHit and NoPrize flags** (`Init_Timer_and_Bonus_Flags` / `lose_life` / `Use_Continue` / `loc_BCEA`)
When `$FFFFFC36` is set, `Init_Timer_and_Bonus_Flags` reloads the timer **and** clears both bonus flags: `sf (NoHit_Bonus_Flag); sf (NoPrize_Bonus_Flag)` (kid.asm:6559-6560). Native now clears both `level_damage_taken` and `level_prize_collected` in `reset_current_level_runtime_state_for_respawn` and `maybe_begin_pending_level_skip_resume`, so death/continue respawns and cross-level teleporter resumes restore the NoHit/NoPrize bonus flags together. Regressions `fc36_respawn_reset_clears_nohit_and_noprize_flags` and `fc36_level_skip_resume_clears_nohit_and_noprize_flags` cover the two live reset paths. Kind: fixed-candidate. `crates/kid-core/src/level.rs`, `crates/kid-core/src/boot.rs`, `crates/kid-core/src/tests/level_tests.rs`.

### Low severity

**Native grants 66-frame post-respawn invuln after *every* death; the ROM only grants it when the kill latched `Just_received_damage`** (`Check_for_recent_damge` / `loc_B72C` / `loc_BC40` / `Crushed_to_Death` / `loc_9142`)
In the ROM, post-damage invulnerability is the latched `Just_received_damage` byte (`$FFFFFA73`): `Check_for_recent_damge` (kid.asm:14633) skips all damage while it is set, and the cosmetic flash thread clears it only after its 66-frame cycle (kid.asm:15214). It is `st`-set **only** by depleting contact/projectile damage at `loc_B72C` (kid.asm:14657); `lose_life`/`Teleport`/`loc_6E2`/`Load_InGame` never write it. The two non-damage death entries — `Crushed_to_Death` (kid.asm:14571, murder wall) and `loc_9142` (kid.asm:10549-10552, pit fall) — branch to `Death` without setting it, so on those respawns the Kid is immediately vulnerable. Native unconditionally seeds `invulnerable_frames = PLAYER_DAMAGE_INVULNERABLE_FRAMES` (66) at the end of the Respawning arm (boot.rs:7696-7700) for all causes, after clearing `just_received_damage` at the respawn reset (level.rs:17987-17988). Low because respawn lands at level start where immediate re-damage is rare, but it is an authoritative damage-immunity difference. Kind: deviating.

**RESOLVED candidate — death entry clears `Extra_hitpoint_slots`, retaining no DP slots across death/respawn** (`Death` / `lose_life`)
Reported by the death-cause-routing unit as the same root as the high-severity carry above (the `Death` routine zeroes the field at kid.asm:14719 and `lose_life` again at kid.asm:14764). Native now clears `progression.extra_hitpoint_slots` in the live death-hidden transition. Merged into the high-severity entry; retained here only to record the death-cause unit's independent corroboration. Kind: fixed-candidate.

**Resolved — `resolve_frame_hazards` checks level-timer death before pit-fall; the ROM defers timer death one frame, so a coincident fall picks the wrong windup path** (`loc_9142` / `Crushed_to_Death` / `Character_CheckCollision`)
Native now ticks the timer and queues `VoiceNoTime`, then allows the immediate `sub_902A` `loc_9142` pit branch to win before falling back to the deferred timer-death path. This matches the ROM split: `Decrease_Time_Left` writes collision_type=4 and plays no-time (kid.asm:15494-15502), while the pit kill branches to `Death` immediately with `d7=1` (kid.asm:10454/10550). Covered by `loc_9142_pit_death_wins_over_same_frame_timer_expiry`.

**Resolved — `fell_below_level` fires regardless of y-velocity direction; the ROM pit kill is only reachable from the downward floor-probe branch** (`sub_902A` / `loc_9142` / `loc_908C`)
Native `fell_below_level` now returns false when `y_velocity < 0`, matching `sub_902A`: the `bmi loc_908C` upward branch skips the `Level_height_pixels` compare, while only the non-negative y-velocity branch can reach `loc_9142` pit death (kid.asm:10440-10455, 10476-). Covered by `loc_908c_sub_902a_upward_below_level_height_does_not_trigger_pit_death`.

**GameOver hold runs the full 419-frame timer before the continue decision; the ASM reaches the continue screen in ~34 frames when continues remain** (`loc_D0C0` / `loc_D15E` / `loc_D25E` / `Continue_Screen` / `loc_D2CE`)
The ROM runs only a short shared fade tail before the continue decision: `loc_D0C0` hibernates one frame and `loc_D15E` decrements `$FFFFF876` from `$100` by `$10` until it equals `$70` (~9 iterations) before `loc_D17E` → `loc_D25E` (kid.asm:16368, 16416-16420, 16472); the `$1A3` (419) frame wait at `loc_D2CE` belongs only to the no-continues path. Native applies `PLAYER_GAME_OVER_HOLD_FRAMES=419` unconditionally (`if remaining_frames > 1`) before deciding continue-vs-title (boot.rs:7760-7768, constants.rs:508), so when continues remain the player waits ~419 frames before the interactive continue screen rather than ~34. The continue-vs-title routing itself is correct; only the hold ordering/duration deviates. Adjacent to the excluded continue/game-over screen (shell) scope. Kind: deviating.

**`sub_B43A` WarpCheat dest-level override branch absent from the native floor probe** (`sub_B43A` / `loc_B482` / `WarpCheatStart_LevelID` / `WarpCheatDest_LevelID`)
`sub_B43A`'s entry preamble (kid.asm:14352-14364) implements a developer warp cheat: when `Character_Movement == MoveID_Crawling`, the level is `WarpCheatStart_LevelID` (1), the Kid is at exact pixel `x=$09D3,y=$005F`, and Button_B is held, it writes `move.w #WarpCheatDest_LevelID,(Current_LevelID).w` (`$32`), sets `collision_type=colid_kidbelow` and `object_meta=$A0`. This is the only non-HundredKTrip secret level-destination routing path in the engine. The native port `walking_floor_support_exists_at_current_position` (movement.rs:5664, live-called at 2858/3115/4217/4234) is faithful from `loc_B4A0` onward but entirely omits the crawling-check + warp-cheat block; no `Current_LevelID` override exists in `movement.rs`. Low: a cheat reachable only via held B at one exact crawl position, no effect in normal play — flagged because the unit asked whether *any* native non-100K secret routing path exists; it does not. Kind: missing.
