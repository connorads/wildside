# Dead-Helper Census

A codebase-wide follow-up to the [enemy fidelity audit](enemy-fidelity-audit.md). That audit found a systemic failure mode in `enemies.rs` — ASM-faithful pure helpers that are modelled and unit-tested but carry `#[cfg_attr(not(test), allow(dead_code))]` and are never wired into the live step/combat path. This census asks: **how far does that pattern extend across the whole crate, and where is wiring highest-leverage?**

## Headline findings

1. **The pattern is real and large, but its epicentre is NOT `enemies.rs`.** `enemies.rs` turns out to be overwhelmingly *wired* — a comprehensive live family dispatch (`step_frame -> refresh_active_roster -> step_active_enemies_with_rng -> per-family step_*`), with most of its 1,190 dead-gated fns being **stale attributes** on leaf helpers that genuinely feed live orchestrators. This **revises the enemy-fidelity-audit's file-level "runtime falls back to generic pacers" framing**: the enemy *behaviour* gaps it found are real, but they are missing sub-branches *inside* wired orchestrators, not a wholesale generic fallback.

2. **The true unwired epicentre is `combat.rs` (entire boss subsystem), `level.rs` (loading + block decode), `helmets.rs` (Diamond Power weapons), `platforms.rs` (all platform physics), `weather.rs` (geyser/storm script machines), and `lib.rs` (GEMS audio).** In these files the live runtime uses generic fallbacks or inline approximations while a complete, unit-tested ASM model sits dark.

3. **Almost nothing is genuinely untested.** After correcting for the test layout (tests live in `crates/wildside-core/src/tests/*.rs`, separate files — the first extractor pass missed them and over-reported "uncalled" helpers), the count of helpers called by *nothing at all* collapses to a handful per file. The helpers are verified models; they are simply not connected.

4. **Two distinct unwired shapes:** *dead-calling-dead* chains (a helper is called, but only by other dead-gated helpers, so the whole subtree is dark) and *stale attributes* (the helper IS reached from live code — the attribute is just obsolete and should be removed). Stale-attribute removal is a near-zero-risk hygiene win that shrinks the census and stops masking genuinely-dead code.

## Methodology

- **Extractor** (`scripts/dead_helper_census.py`): scans `wildside-core/src/*.rs` for items carrying `allow(dead_code)`, captures name/kind/line, ASM labels (from doc comments + embedded in fn names), and a crate-wide call-site split (test vs non-test, treating `src/tests/*.rs` and inline `#[cfg(test)]` mods as test context). Output: `.cache/audit/dead-helper-census.json`.
- **11 synthesis agents** (one per file >=30 dead-gated items): cluster the helpers by mechanic/ASM region, then spot-read source to resolve each helper's true wiring status — distinguishing *genuinely-wired-stale-attribute* from *dead-calling-dead* from *detection-artefact* from *genuinely-untested-model*. The agents grepped the test tree directly, which is how the extractor's test-layout blind spot was caught.
- **Caveat:** the extractor's call-site counts are first-order (regex `name(`); they cannot by themselves separate a genuinely-live caller from a dead-gated one. The wiring-status splits below are the agents' resolutions. Treat counts as estimates, the clusters and ASM labels as the durable signal.

## Where to wire first (highest-leverage unwired clusters)

Each file's synthesis agent named its 1–3 highest-leverage unwired clusters — wiring them resolves the most behaviour for the least surface. Collected and grouped by subsystem:

- **`combat.rs` — collision_shooter (generic collision/shooter primitives: sub_1FA2 solid-overlap resolution, sub_21F8 kid hitbox, sub_226A projectile overlap, sub_1F52/sub_9832 support overlap)**: These are ENGINE-generic, not boss-specific. Wiring first_solid_overlap_resolution_sub_1FA2 and support_overlap_detected_sub_1F52 corrects solid/support collision for blocks (#139/#140/#143), Kid, and every enemy at once - maximum behaviour per unit of wiring surface, and directly unblocks open block bugs.
- **`combat.rs` — boss_head_movement (sub_39846 stepper + six per-head wrappers)**: A single small dead-calling-dead chain: wiring the base sub_39846 stepper and its wrappers into the boss step path animates all boss heads (boomerang, shishka, bagel) that currently run on generic movement, gating the boss-fight TAS frontier. One stepper, broad effect.
- **`combat.rs` — sprite_render (loc_12B8 sprite chunk, loc_141A DMA upload)**: Generic VDP sprite/DMA primitives that, if the native renderer is meant to be ROM-faithful, would correct sprite chunking/priority across all objects rather than per-enemy - medium-confidence high reach, pending confirmation it is not already superseded by the live renderer.
- **`level.rs` — Enemy loading / spawn manager + spawn-position decode (manage_enemy_loading_*, enemy_layout_*, decode_spawn_positions_loc_11BD2)**: Directly the enemy-fidelity-audit root cause: a complete ASM-faithful spawn/load state machine sits modelled and tested but unwired while enemies.rs runs a generic fallback. ## Reading

This census is a **wiring map, not a defect list**. A "wired" verdict does not mean a subsystem is *correct* — only that the live path reaches it (the enemy-fidelity audit shows wired code can still miss sub-branches). An "unwired" verdict means a complete, unit-tested ASM model exists but the runtime uses a generic fallback or inline approximation instead.

Two follow-on workstreams fall out of this:

1. **Wiring** (behaviour): connect the unwired models above into the live step/combat/render path, highest-leverage first, each verified against an oracle scenario that actually exercises the subsystem. **Prerequisite:** the idle oracle sweep does not exercise bosses, Diamond Power weapons, platforms, or weather scripts — wiring these needs new enemy/object-active oracle scenarios first, or it ships unverified.
2. **Hygiene** (no behaviour change): remove stale `cfg_attr(not(test), allow(dead_code))` attributes from the ~genuinely-wired helpers (notably most of `enemies.rs` and `terrain.rs`). This shrinks the census, restores the compiler's dead-code warning as a real signal, and stops genuinely-dead code from hiding behind a blanket allow.
