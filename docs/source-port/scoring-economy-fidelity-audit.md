# Scoring & Prize-Economy Fidelity Audit

Adversarially-verified per-unit audit of the Kid Chameleon source-port scoring and prize-economy subsystem. The dominant failure pattern is the recurring source-port disease: ASM-faithful pure helpers exist and are unit-tested but carry `#[allow(dead_code)]` / `#[cfg_attr(not(test), allow(dead_code))]` and are never wired into the live frame step, so the runtime either does nothing or falls back on an invented substitute. The starkest live-mechanic absence was the Hundred-K-Trip timer/teleport path; it is now fixed-candidate for the timer countdown and terminal `loc_DA4A` Teleport state, with the intermediate `loc_D980` object-cleanup/fade sequence still approximate. The previous 9-life award cap is now fixed-candidate too: award paths can count past 9 and the live HUD path applies the ROM's `loc_BF2A` 99-life clamp.

## Confirmed gaps

### High severity

**RESOLVED candidate — Hundred-K-Trip 60-frame timer (`$FFFFFB4C`) decrements per live frame and reaches the terminal teleport state** (`loc_7452` / `loc_10AC2` / `loc_DA4A`)
ASM main-loop `loc_7452` (kid.asm:7578-7582) runs every in-game frame: after `Hibernate_Object_1Frame` it does `tst.w ($FFFFFB4C).w; beq.s loc_7464; subq.w #1,($FFFFFB4C).w; beq.w loc_D980` — a nonzero timer is decremented each frame and, on reaching zero, control jumps to the `loc_D980` warp body. Native now calls `step_hundred_k_trip_timer_loc_7452` from the live `step_frame` gameplay path before the rest of the frame advances, so the arm from `loc_10AC2` counts `0x3C -> 0` only while `BootState::InGame`. On zero it applies the existing `end_credits_hundred_k_trip_teleport_loc_DA4A` constants and enters the native `begin_level_entry` Teleport shell for destination level `$1F`. Regression `hundred_k_trip_timer_loc_7452_counts_down_and_enters_teleport_loc_da4a` covers the full 60-frame countdown, score sentinel, level swap, helmet reset, `StartingLevel` shell, and preserved `$20/$48F` PlayerStart. Kind: fixed-candidate. `crates/kid-core/src/lib.rs`, `crates/kid-core/src/level.rs`, `crates/kid-core/src/tests/combat_tests.rs`.

**PARTIAL remaining debt — Hundred-K-Trip `loc_D980` object cleanup/fade body is still compressed to the terminal `loc_DA4A` Teleport state** (`loc_D980` / `loc_D99E` / `loc_D9EA` / `loc_DA16` / `loc_DA30`)
The ASM warp body reached from `loc_7452` at timer-zero (`loc_D980`..`loc_DA4A`, kid.asm:17007-17092) clears object-collision longwords on every non-current object, runs `Delete_AllButCurrentObject`, performs a palette fade (`loc_DA16`/`loc_DA30`), then at `loc_DA4A` (kid.asm:17083) writes `Score=1000001`, `PlayerStart_X=$20`, `PlayerStart_Y=$48F`, `Current_LevelID=$1F`, clears `Current_Helmet`, sets `$FFFFFC29`, and branches through `Teleport`. Native now wires the terminal `loc_DA4A` helper into production, including a `pending_player_start_override_loc_11bd2` latch so destination Load_InGame preserves `$20/$48F` instead of reading the destination header. It still skips the intermediate `loc_D980` object teardown and fade hibernate sequence; the code marks this with `TODO(fidelity)` in `apply_hundred_k_trip_teleport_loc_da4a`. Kind: partial. `crates/kid-core/src/level.rs`, `crates/kid-core/src/lib.rs`.

The Hundred-K-Trip authoritative level-flow effect is now live: timer countdown → score sentinel → level swap to `$1F` → Teleport shell. The remaining risk is visual/timing fidelity during the `loc_D980` cleanup/fade interval, not total mechanic absence. The only adjacent prior-doc entry is `level-loading-fidelity-audit.md:211-212`, which tracks a *different* facet (the EOL flagpole path spuriously calling the arm helper).

### Medium severity

**RESOLVED candidate — life awards are uncapped, with the ROM 99-life ceiling applied only by the live HUD path** (`PrizeAnkhCollected_Init` / `Prize10000Points_Init` / `loc_10AAE` / `loc_BF2A` / `life_display`)
Every ASM life-award site is a bare `addq.w #1,(Number_Lives).w` with no per-award cap: the Ankh award `PrizeAnkhCollected_Init` (kid.asm:21228), the Prize10000 50K-boundary award `loc_10AAE` (kid.asm:22373), the alternate score-boundary award (kid.asm:16877), and the Diamond-Power extra-life (kid.asm:44975). The only lives clamp in the ROM is the per-frame HUD routine `loc_BF2A` (kid.asm:15527-15531): `cmpi.w #100,d0; blt.s life_display; moveq #99,d0; move.w d0,(Number_Lives).w`. Native `add_life` now uses a bare saturating increment instead of the old `< 9` guard, and the live level-frame HUD path calls `hud_lives_clamp_loc_BF2A` before trace/render sampling. Regressions `ankh_life_award_loc_fefe_allows_tenth_life_before_hud_clamp_loc_bf2a`, `add_life_loc_10aae_allows_lives_above_nine_until_hud_clamp_loc_bf2a`, and `live_hud_path_loc_bf2a_clamps_lives_to_ninety_nine` replace the old 9-cap pins. Kind: fixed-candidate. `crates/kid-core/src/combat.rs`, `crates/kid-core/src/lib.rs`, `crates/kid-core/src/tests/combat_tests.rs`, `crates/kid-core/src/tests/level_tests.rs`.

**RESOLVED candidate — clock prize applies the ASM +1 second before the +3 minutes (and cap carry)** (`PrizeClockCollected_Init` / `loc_FFDE` / `loc_FFFC` / `loc_10002`)
ASM `PrizeClockCollected_Init` runs an explicit one-second BCD increment of the level timer (`Time_Seconds_low_digit` +1, with carry into the tens digit at `#$A` and into `Time_Minutes` at `#6`, kid.asm:21271-21279) immediately before reading `Time_Minutes` and adding 3 minutes at `loc_FFDE` (kid.asm:21282-21288). Native `add_clock_bonus` now adds `LEVEL_TIMER_CLOCK_COLLECT_SECONDS=181`, caps to 10:00, and still resets `sub_frames` to 1 for `loc_FFFC`; the next countdown tick cancels that extra second so the live display nets a clean +3:00. The `clocks_collected` increment and speed-bonus elapsed-time formula remain on flat `$B4` via `LEVEL_TIMER_CLOCK_BONUS_SECONDS`, matching `loc_C10A`. Regression tests cover the post-tick clean +3:00 and the 6:59→10:00 cap boundary. Kind: fixed-candidate. `crates/kid-core/src/types.rs`, `crates/kid-core/src/combat.rs`, `crates/kid-core/src/trace.rs`, `crates/kid-core/src/constants.rs`.

**RESOLVED candidate — Continue-prize pickup plays `sfx_Coin_prize` (`$2C`) on the increment frame** (`CharacterCollision_TouchCoin` / `CharacterCollision_TouchNonHelmetPrize` / `CharacterCollision_TouchSpecialPrize` / `Character_CheckCollision`)

Regression `prize_content_continue_queues_coin_sound_on_increment_loc_b952` pins the counter increment and `$2C` cue together. ### Low severity

**RESOLVED candidate — `add_score` awards one life per `loc_10AAE` quotient change, not one per crossed boundary** (`loc_10AAE` / `Prize10000Points_Init`)
The ROM compares `divu.w #50000` quotients of the pre-add score (d0) and post-clamp score (d1) and issues a single `addq.w #1,(Number_Lives).w` only when they differ (kid.asm:22369-22373). Native `add_score` now mirrors that branch: compare old/new post-cap quotients and call `add_life()` once when they differ. Regression `add_score_loc_10aae_crossing_multiple_50k_boundaries_awards_one_life` covers a 40,000 -> 110,000 jump that crosses two score intervals but should still award one life. Kind: fixed-candidate. `crates/kid-core/src/combat.rs`, `crates/kid-core/src/tests/level_tests.rs`.

**The `blocks-fidelity-audit.md` "dead mechanic" claim for the Continue counter is contradicted by the ASM; the native increment is authoritative and the backlogged no-op "fix" would regress it** (`CharacterCollision_TouchCoin` / `Continue_Screen` / `Use_Continue`)
`blocks-fidelity-audit.md:90` states `Number_Continues` is "accessed nowhere in the disassembly — the Continue prize is a dead mechanic" and the native increment "has no in-game effect", and its backlog row (line 142) proposes making the Continue arm a no-op on the counter. That premise is wrong: `kid.asm` contains a high/NUL byte so plain `grep` treats it as binary and prints nothing, while `grep -a` reveals five live accesses — increment at `TouchCoin` (kid.asm:14905), and at the game-over Continue screen `tst.w (Number_Continues).w; bne.w Continue_Screen` (16473) gates whether a continue is offered, the value is displayed (16523), and `Use_Continue` (16563) does `subq.w #1` then resets `Number_Lives` to 3, clears helmet/diamonds and `Teleport`s (an authoritative level restart). Native already implements this authoritatively (`boot.rs:7764` gates the ContinueCountdown on `number_continues > 0`; `boot.rs:7786` decrements and resets lives to 3). The native increment is therefore correct and load-bearing; applying the backlogged no-op fix would break the continue economy. Flagged here so the stale prior-doc claim and stale native cite (`combat.rs:8769`, now `8802-8805`) are corrected, not actioned as a removal. Kind: deviating (documentation/regression-risk). `crates/kid-core/src/combat.rs:8802`, `crates/kid-core/src/boot.rs:7745`, `docs/source-port/blocks-fidelity-audit.md:89-90`, `docs/source-port/blocks-fidelity-audit.md:142`.
