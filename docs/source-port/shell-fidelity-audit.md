# Game Shell & HUD Fidelity Audit

Adversarially-verified per-unit audit of the Kid Chameleon source-port game shell — pause, death/game-over/continue, the level clock, the HUD, the title/attract/demo loop, and the 2P state bank. The dominant failure pattern is the one that recurs across the codebase: ASM-faithful pure helpers exist and are unit-tested but carry `#[cfg_attr(not(test), allow(dead_code))]` and are never wired into the live frame step, so the runtime falls back on an invented substitute. Nowhere is this starker than the pause subsystem, where the entire interactive Restart-Round / Give-Up menu — cursor select, life cost, helmet/HP reset, level restart, and the last-life forced game-over — is fully modelled and unit-tested yet collapsed live to a single boolean freeze, so a player can never restart a round or give up. The same dead-helper pattern accounts for the remaining missing Allow_Pausing entry gate.

## Confirmed gaps

### High severity

**Pause-menu Restart-Round / Give-Up menu (incl. last-life forced game-over) is entirely unwired; live pause can only continue** (`Game_Paused_Loop` / `loc_6B0E` / `Game_Paused_ChkStart` / `loc_6B62` / `loc_6B68` / `loc_6C0A` / `loc_6C3E` / `sub_6874` / `loc_687C`)
The ROM pause loop (`Game_Paused_Loop`, kid.asm:6829) reads the joypad each paused frame and runs an interactive two-option menu via `Pause_Option`: Up/Down (`loc_6B0E`) moves the cursor between Continue (option 0) and Restart-Round / Give-Up (option 1), the label being lives-gated at `restart_text` (kid.asm:6741 — `MapUnc_PauseMenu_Restart` when `Number_Lives>1`, else `MapUnc_PauseMenu_GiveUp`). On Start (`Game_Paused_ChkStart`, kid.asm:6859): option 0 continues (`loc_6B68`); option 1 always costs a life (`subi.w #1,(Number_Lives)`), then if lives remain resets state (`clr Extra_hitpoint_slots`, `clr Current_Helmet`, `move.w #2,Number_Hitpoints`, `st $FFFFFC36`) and restarts the level (`jmp loc_6E2`); if it was the last life (`loc_6B62`) it sets `Game_Paused=3`, and on unpause `loc_6C0A` plays `sfx_Voice_bummer`, forces the Kid into a dying state (`$38(a4)=4`, `$3A(a4)=$30`), sets `Number_Lives=1`, and proceeds to game-over. The native models every step faithfully — the up/down/start handlers, the lives-gated text helper, and `pause_menu_unpause_exit_loc_6C0A` reproduce the exact constants (`kid_action=4`, `kid_action_param=0x30`, `number_lives=1`, `sfx_Voice_bummer=$68`) — but every handler carries `#[cfg_attr(not(test),allow(dead_code))]` and is called only from `#[cfg(test)] mod tests` (boot.rs test mod begins at 7843; refs at 8945-9110, plus tests.rs / tests/boot_tests.rs). The live unpause path `handle_start_press` (boot.rs:6512-6545) merely flips `self.paused`/arms `pause_toggle_pending`, `apply_pending_pause_toggle` (lib.rs:2192-2194) does `self.paused = !self.paused`, and `step_lifecycle` (boot.rs:7823-7837) is a pure freeze gate; there is no `Pause_Option`, no Up/Down, no life cost, no helmet/HP reset, no level restart, and no last-life game-over. The consequence is authoritative (level restart, Kid object-identity dying state, forced game-over) so this is in scope despite touching the advisory `Number_Lives` counter. The `boot.rs:7831` comment acknowledges the boolean-gate simplification but is not a `// DEVIATION` marker. This merges the `pause-menu-restart-giveup` interactive-menu gap with the `pause-exit-lastlife-death` last-life-exit and selection gaps — both units describe the same unwired feature, split only between the input (decision) side and the unpause (consequence) side. Kind: helper-unwired. `crates/kid-core/src/lib.rs:2192-2194`, `crates/kid-core/src/boot.rs:6512-6545`, `crates/kid-core/src/boot.rs:7823-7837`, `crates/kid-core/src/boot.rs:1683`, `crates/kid-core/src/boot.rs:1718`, `crates/kid-core/src/boot.rs:1775`, `crates/kid-core/src/boot.rs:1853`.

**RESOLVED candidate — level timer seed now includes Init_SpriteAttr_HUD's `addq #1` pre-decrement second** (`Init_Timer_and_Bonus_Flags` / `Init_SpriteAttr_HUD` / `Decrease_Time_Left` / `loc_C0CC`)
During level load the ASM seeds the timer in two routines. `Init_Timer_and_Bonus_Flags` (kid.asm:6551-6564) sets `Time_Minutes=3` and clears both seconds digits and `Time_Frames` (display 3:00); then `Init_SpriteAttr_HUD` (sub_14244, kid.asm:27087-27101, called at kid.asm:24124 during title-card graphics setup before gameplay is interactive) does `addq.w #1,(Time_Seconds_low_digit)` and `move.w #1,(Time_SubSeconds)`, so the seeded display at gameplay start is 3:01 (181 displayed seconds). Native now models that with `LEVEL_TIMER_START_SECONDS=181` and `sub_frames=1`, while the separate `LEVEL_TIMER_COMPLETION_BASE_SECONDS=180` keeps `loc_C0CC`'s `addi #$B4` completion-time formula on the ROM base. Focused regressions cover the 3:01 seed, the first-tick 3:01→3:00 normalisation, the later 60-frame cadence, and the full countdown expiry frame. Human playtest should still validate the visible HUD/timer-death cadence. Kind: fixed-candidate. `crates/kid-core/src/types.rs`, `crates/kid-core/src/constants.rs`, `crates/kid-core/src/combat.rs`, `crates/kid-core/src/trace.rs`.

### Medium severity

**Pause-entry handler never consults Allow_Pausing; pause toggles in ROM-forbidden windows (fade-in / teleport / warp)** (`loc_74C8` / `loc_74B0` / `Teleport` / `sub_73D0` / `loc_7420`)
ASM `loc_74C8` (kid.asm:7631-7637) gates pause entry on a two-stage check: A-not-held AND `tst.b (Allow_Pausing).w; beq.w loc_7452`. `Allow_Pausing` ($FFFFFB56, variables.asm:122) is BSS-zero at boot, set (`$FF`) only when the per-level fade-in worker `sub_73D0` finishes (`loc_7420`, kid.asm:7561), and cleared (`$00`) on every `Teleport` (kid.asm:14773) — the shared tail for death (lose_life), telepad warp, level-skip-cheat warp, and level-clear advance. The ROM thus forbids pause from each level/death/warp transition until the next level's fade-in completes (~17 frames at `+$10`/frame past `$100`), plus across the whole inter-level transition. Native `handle_start_press` (boot.rs:6512-6545) gates pause only on `player_lifecycle==Alive`, `boot_state==InGame`, and `!input.a`; it never reads any allow-pausing state (`apply_pending_pause_toggle`, lib.rs:2192-2194). The lifecycle guard happens to shadow the death and level-clear cases (those leave non-`Alive` states), but the early-InGame level fade-in window and the telepad/level-skip warp windows leave the player `Alive+InGame`, so pressing Start there sets pause in frames the ROM forbids. Pause is authoritative (halts object stepping and Kid/diamond-power motion at lib.rs:2088-2098), so a player/TAS observes the divergent toggle. This is a TODO (boot.rs:5765-5766), not a `// DEVIATION`. Kind: missing. `crates/kid-core/src/boot.rs:6512-6545`, `crates/kid-core/src/lib.rs:2192-2194`, `crates/kid-core/src/boot.rs:5765-5766`.

**RESOLVED candidate — CONTINUE? screen consumes a continue only on Start, matching `Ctrl_Held` bit 7** (`loc_D350` / `loc_D3AA` / `Use_Continue` / `Continue_Screen`)
In both ROM continue-countdown wait loops the only input that grabs a continue is Start: `loc_D350` (kid.asm:16530-16531) and `loc_D3AA` (kid.asm:16557-16558) each do `tst.b (Ctrl_Held).w; bmi.s Use_Continue` — `bmi` tests bit 7 of the SACBRLDU button byte (variables.asm:30), i.e. Start only. Native gates the live `ContinueCountdown` use path on `input.start` and has a regression asserting A/B/C alone leave the countdown running. Kind: fixed-candidate. `crates/kid-core/src/boot.rs`, `crates/kid-core/src/tests/movement_tests.rs`.

**RESOLVED candidate — Use_Continue clears extra_hitpoint_slots** (`Use_Continue`)
ASM `Use_Continue` (kid.asm:16563-16575) resets the run — `Number_Lives=3`, `Current_Helmet=0`, `Number_Diamonds=0`, `Number_Hitpoints=2`, and crucially `clr.w (Extra_hitpoint_slots).w` (kid.asm:16572) — then branches directly to `Teleport`, skipping the `lose_life` body, so this is its own clear. Native now clears `progression.extra_hitpoint_slots` in the live `ContinueCountdown` Start path before respawn reset, and `use_continue_clears_extra_hitpoint_slots_loc_d3c4` covers a previously earned Diamond-Power extra-HP slot. Kind: fixed-candidate. `crates/kid-core/src/boot.rs`, `crates/kid-core/src/tests/movement_tests.rs`.

**RESOLVED candidate — Continue countdown includes the `loc_D3AA` second Start window** (`loc_D350` / `loc_D3AA` / `Continue_Screen` / `loc_D3F0`)
The ROM continue screen has two countdown loops that both poll Start for `Use_Continue`: `loc_D350` runs `$123`(291) frames, then (after kicking the text/number objects into the falling fade at `loc_D372`/`loc_D386`) `loc_D3AA` runs another `$EF`(239) frames, each `tst.b (Ctrl_Held); bmi.s Use_Continue`; only after `loc_D3AA` expires does `loc_D3F0` return to title (kid.asm:16526-16560). Native now includes the `$1C` initial hold, `$123` first window, and `$EF` second window in `CONTINUE_COUNTDOWN_FRAMES`, preserving the Start poll throughout the lifecycle. Regressions assert the old timeout boundary remains in CONTINUE? and Start during the second window spends the continue. Kind: fixed-candidate. `crates/kid-core/src/boot.rs`, `crates/kid-core/src/constants.rs`, `crates/kid-core/src/tests/movement_tests.rs`.

**RESOLVED candidate — Per-player state bank preserves Extra_hitpoint_slots** (`sub_8A4` / `loc_8B4` / `loc_8BA` / `sub_8C2` / `loc_8D2` / `loc_8D8`)

Kind: fixed-candidate. `crates/kid-core/src/types.rs`, `crates/kid-core/src/level.rs`, `crates/kid-core/src/tests/helmet_tests.rs`, `crates/kid-core/src/tests/level_tests.rs`.

**Options control-scheme remap (Permute_ABCButtons) never applied to live input — schemes 1-5 have no gameplay effect** (`ReadJoypad` / `Permute_ABCButtons` / `sub_CCE` / `loc_CE8`)
The ROM calls `Permute_ABCButtons` inside `ReadJoypad` immediately after each `Joypad_ReadFromHardware` and *before* storing the result (kid.asm:1361-1363 for `Ctrl_1`, 1366-1368 for `Ctrl_2`), so the remap rewrites the very bytes downstream gameplay consumes. The routine (kid.asm:1458-1476) skips demo mode, early-returns on scheme 0, then jumps a five-entry table remapping bits 4/5/6 (B/C/A → Speed/Jump/Special) via `bclr`/`bset`. Native models it faithfully as `with_abc_buttons_permuted` (types.rs:1075) with unit tests, but the helper has zero live callers — the live input store path (lib.rs:1965-1980) and `gameplay_input` (lib.rs:2583) read button fields directly, and `options_controls_scheme` (lib.rs:259) feeds only the options-menu label renderer (boot.rs:4457, scene.rs:1194). TAS/demo parity never catches this because the ASM itself skips the remap in demo mode, so every oracle trace exercises only scheme 0. Found by the wave-2 completeness critic; confirmed by an independent refuter. Kind: helper-unwired. `crates/kid-core/src/types.rs:1075`, `crates/kid-core/src/lib.rs:1965-1980`, `crates/kid-core/src/lib.rs:2583-2606`, `crates/kid-core/src/boot.rs:4457`.

**Options Fast-Action Speed inversion (`not.b Ctrl_A_Held`) never applied — Fast and Normal play identically** (`loc_749C` / `loc_74B0`)
Every player-update frame the ROM tests `Options_Suboption_Speed` ($FFFFFDC9; Normal=0, Fast=-1 per variables.asm:205) and, when Fast Action is selected, executes `not.b (Ctrl_A_Held).w` (kid.asm:7619-7621, demo-mode skipped at 7617-7618), inverting the held run latch so the run modifier becomes hold-to-walk / tap-to-run; downstream `loc_9974` (kid.asm:11509-11516) selects run accel `$20` vs walk accel `$10` from that latch. Native stores `options_speed_button_fast` (lib.rs:261) from the menu and renders its label (boot.rs:4639) but never consumes it in `gameplay_input` or movement; the faithful helper `with_speed_option_a_inverted` (types.rs:1048-1050) is called only from tests (combat_tests.rs:15980-16008). Found by the wave-2 completeness critic; confirmed by an independent refuter. Kind: helper-unwired. `crates/kid-core/src/types.rs:1048`, `crates/kid-core/src/lib.rs:261`, `crates/kid-core/src/lib.rs:2583-2606`, `crates/kid-core/src/boot.rs:4639`.

### Low severity

**Entire pause-render cluster (darken palette + art DMA + tile save/restore + sprite-hide) is unwired; live pause is a boolean freeze** (`sub_6874` / `loc_687C` / `loc_6894` / `loc_68AC` / `loc_690C` / `loc_693A` / `loc_695C` / `loc_69AE` / `loc_6B68` / `loc_6BA4` / `Pause_DarkenPalette`)
ASM `sub_6874`/`loc_687C` runs every paused frame: darken the palette, upload it, hide sprites whose tile index falls in `$676..$68E`, DMA the pause-menu art to VRAM `$CEC0`, and save the five-row plane-A tile region under the menu into `Decompression_Buffer` (restored at `loc_6B68` on unpause) with plane-edge wrap handling. Native has ASM-faithful, unit-tested pure helpers for every step (`pause_menu_gate_loc_687C`, `hide_pause_menu_overwritten_sprites_sub_6874`, `pause_menu_art_total_bytes_loc_690C`, `pause_menu_tile_save_plan_loc_695C`, `pause_menu_tile_restore_plan_loc_6B68`, `pause_darken_palette_loc_6C70`), but all carry `#[allow(dead_code)]` and are referenced only from `tests.rs` and the `#[cfg(test)] mod tests` block; grep finds zero production callers. The live pause path is a boolean freeze (`if self.paused { return false }` at boot.rs:7823, with a comment deferring palette darkening to the rendering layer; lib.rs:2082-2086 documents the pause-tail VDP/sprite work as "not modelled"). All consequences here are visual/VDP only (no menu overlay, no engine palette darken, background redraw on unpause left to the renderer) with no motion/damage/lifecycle effect, hence low; the interactive menu-selection path is the separate high-severity gap above. Kind: helper-unwired. `crates/kid-core/src/boot.rs:1107`, `crates/kid-core/src/boot.rs:1126`, `crates/kid-core/src/boot.rs:1158`, `crates/kid-core/src/boot.rs:1335`, `crates/kid-core/src/boot.rs:1538`, `crates/kid-core/src/boot.rs:1901`, `crates/kid-core/src/boot.rs:7823`.

**step_fullscreen_palette_fade_sub_73D0 models Allow_Pausing-set but is dead code, never wired to engine pause state** (`sub_73D0` / `loc_7420`)
The only native representation of ASM `st (Allow_Pausing).w` (kid.asm:7561) is a struct-local bool on `FullscreenPaletteFadeSub73D0` set at level.rs:12483 when the fade worker completes. That function is `#[allow(dead_code)]` and called only from tests (`boot_tests.rs:3730` and `tests.rs` re-exports) — there is no production caller, no engine field named `allow_pausing`. So the ASM's set-on-fade-complete behaviour is unit-tested but unreachable from the live frame step, and the flag is disconnected from the engine pause gate. This is the helper-unwired mechanism behind the medium Allow_Pausing entry-gate gap above; low on its own with no independent observable effect. Kind: helper-unwired. `crates/kid-core/src/level.rs:1710`, `crates/kid-core/src/level.rs:12471-12487`, `crates/kid-core/src/level.rs:12483`.

**No-continue GAME OVER hold omits the `$3C` pre-hold hibernate (60 frames short)** (`loc_D25E` / `loc_D2CE`)
On the no-continues GAME OVER path the ROM hibernates `$3C`(60) frames — the GAME/OVER text fall-in — before entering the `$1A3`(419)-frame Start-skippable hold (`loc_D2CE`); see kid.asm:16491-16499. Native `PLAYER_GAME_OVER_HOLD_FRAMES=419` (constants.rs:506-508) models exactly `$1A3` with no separate 60-frame pre-hibernate, so the automatic title-return arrives ~60 frames (~1s) earlier than the ROM. The parallel continue path did fold its `$1C`(28) pre-pause into `CONTINUE_COUNTDOWN_FRAMES`, so this omission is an inconsistency. Input fidelity is fine (the `$3C` window is a plain `Hibernate_Object` that polls no input, and Start-skip via `bmi`=Start is correctly modelled). Pure hold-duration/visual nuance, hence low. Kind: deviating. `crates/kid-core/src/boot.rs:7653-7654`, `crates/kid-core/src/constants.rs:506-508`.

**Low-time Kid-tracking timer relocation (`sub_BD0A` d7=1 / `loc_BD40`, ≤0:29) missing from live HUD; and `loc_BF2A` 99-life cap unwired** (`End_Decrease_Time_Left` / `sub_BD0A` / `loc_BD40` / `loc_BD38` / `unk_BD8A` / `loc_BF2A` / `life_display`)
Two display-side deviations in the HUD region, both advisory-masked. (1) The live HUD renderer (`push_game_hud`, hud.rs:284, called from scene.rs:4285) always draws the four timer sprites at the fixed `unk_BD8E` positions and never implements the ROM low-time behaviour: when minutes==0 and seconds-tens ≤2 (≤0:29), `End_Decrease_Time_Left` calls `sub_BD0A` with `d7=1` → `loc_BD40` (kid.asm:15307), which hides the minutes digit and colon (x=1, offscreen) and floats the two seconds digits over Kid's head at `kid_x-7`/`kid_x+1`, `kid_y`. The native trace exports `level_timer_seconds` plus camera/kid position, so the renderer has the inputs but performs no threshold check; the `d7=1` mirror and `hud_timer_low_time_check` helper are `#[allow(dead_code)]` test-only. (2) In the exact lives boundary before `life_display`, the ROM caps the live `Number_Lives` RAM at 99 every HUD frame and writes it back (`loc_BF2A`, kid.asm:15527-15531) — the only lives cap in the game; every increment site (kid.asm:16877/21228/44975) is a bare uncapped `addq.w #1,(Number_Lives)`. Native never models this clamp live (`hud_lives_clamp_loc_BF2A` is `#[allow(dead_code)]`, test-only), instead capping at the increment sites with wrong, inconsistent constants: `add_life` (combat.rs:8626) caps at 9 with a comment falsely citing the ASM, while the DiamondPower ExtraLife path (helmets.rs:4811-4812) uses `saturating_add(1)` with no game cap. `number_lives` is advisory (its only authoritative consequence, lives==0 game-over at boot.rs:7616, is unaffected by a 100→99 clamp), so impact is limited to the lives readout near the cap. Kind: missing (low-time relocation) / deviating (lives cap). `crates/kidcli/src/native_player/hud.rs:284`, `crates/kidcli/src/native_player/hud.rs:7-14`, `crates/kid-core/src/boot.rs:417`, `crates/kid-core/src/boot.rs:730`, `crates/kid-core/src/combat.rs:8626`, `crates/kid-core/src/helmets.rs:4811-4812`.

Scout exclusions and units resolved with no gap:

- **level-timer-decrement-and-freezes** — audited full; no gap. The premise (timer running during transforms / FB4B freezes) does not hold: the live timer is suppressed in all windows the ASM freezes it via lifecycle/transform early-returns (step_lifecycle returns false for Dying/LevelComplete/GameOver → refresh_opening_slice early-returns; `gameplay_hibernating_for_transform()` early-returns during form-change flash) rather than mirrored flag bytes. - **title-attract-rotation-demo-handoff** — audited full; no gap. The in-scope idle→demo→title cycle and auto-timeout-vs-manual-Start handoff (mode-clear vs paused-title) are faithfully modelled; per-frame oracle constants were explicitly out of scope.
- **demo-input-stream-no-end-guard** — audited full; no gap. Not re-reported.
