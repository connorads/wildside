# Game Shell & HUD Fidelity Audit

Adversarially-verified per-unit audit of the Kid Chameleon source-port game shell — pause, death/game-over/continue, the level clock, the HUD, the title/attract/demo loop, and the 2P state bank. The dominant failure pattern is the one that recurs across the codebase: ASM-faithful pure helpers exist and are unit-tested but carry `#[cfg_attr(not(test), allow(dead_code))]` and are never wired into the live frame step, so the runtime falls back on an invented substitute. Nowhere is this starker than the pause subsystem, where the entire interactive Restart-Round / Give-Up menu — cursor select, life cost, helmet/HP reset, level restart, and the last-life forced game-over — is fully modelled and unit-tested yet collapsed live to a single boolean freeze, so a player can never restart a round or give up. The `Allow_Pausing` entry gate is now a fixed candidate; the remaining shell gaps are pause-render wiring and game-over hold details.

## Confirmed gaps

### High severity

**Pause-menu Restart-Round / Give-Up menu (incl. last-life forced game-over) is entirely unwired; live pause can only continue** (`Game_Paused_Loop` / `loc_6B0E` / `Game_Paused_ChkStart` / `loc_6B62` / `loc_6B68` / `loc_6C0A` / `loc_6C3E` / `sub_6874` / `loc_687C`)
The ROM pause loop (`Game_Paused_Loop`, kid.asm:6829) reads the joypad each paused frame and runs an interactive two-option menu via `Pause_Option`: Up/Down (`loc_6B0E`) moves the cursor between Continue (option 0) and Restart-Round / Give-Up (option 1), the label being lives-gated at `restart_text` (kid.asm:6741 — `MapUnc_PauseMenu_Restart` when `Number_Lives>1`, else `MapUnc_PauseMenu_GiveUp`). On Start (`Game_Paused_ChkStart`, kid.asm:6859): option 0 continues (`loc_6B68`); option 1 always costs a life (`subi.w #1,(Number_Lives)`), then if lives remain resets state (`clr Extra_hitpoint_slots`, `clr Current_Helmet`, `move.w #2,Number_Hitpoints`, `st $FFFFFC36`) and restarts the level (`jmp loc_6E2`); if it was the last life (`loc_6B62`) it sets `Game_Paused=3`, and on unpause `loc_6C0A` plays `sfx_Voice_bummer`, forces the Kid into a dying state (`$38(a4)=4`, `$3A(a4)=$30`), sets `Number_Lives=1`, and proceeds to game-over. The native models every step faithfully — the up/down/start handlers, the lives-gated text helper, and `pause_menu_unpause_exit_loc_6C0A` reproduce the exact constants (`kid_action=4`, `kid_action_param=0x30`, `number_lives=1`, `sfx_Voice_bummer=$68`) — but every handler carries `#[cfg_attr(not(test),allow(dead_code))]` and is called only from `#[cfg(test)] mod tests` (boot.rs test mod begins at 7843; refs at 8945-9110, plus tests.rs / tests/boot_tests.rs). The live unpause path `handle_start_press` (boot.rs:6512-6545) merely flips `self.paused`/arms `pause_toggle_pending`, `apply_pending_pause_toggle` (lib.rs:2192-2194) does `self.paused = !self.paused`, and `step_lifecycle` (boot.rs:7823-7837) is a pure freeze gate; there is no `Pause_Option`, no Up/Down, no life cost, no helmet/HP reset, no level restart, and no last-life game-over. The consequence is authoritative (level restart, Kid object-identity dying state, forced game-over) so this is in scope despite touching the advisory `Number_Lives` counter. The `boot.rs:7831` comment acknowledges the boolean-gate simplification but is not a `// DEVIATION` marker. This merges the `pause-menu-restart-giveup` interactive-menu gap with the `pause-exit-lastlife-death` last-life-exit and selection gaps — both units describe the same unwired feature, split only between the input (decision) side and the unpause (consequence) side. Kind: helper-unwired. `crates/kid-core/src/lib.rs:2192-2194`, `crates/kid-core/src/boot.rs:6512-6545`, `crates/kid-core/src/boot.rs:7823-7837`, `crates/kid-core/src/boot.rs:1683`, `crates/kid-core/src/boot.rs:1718`, `crates/kid-core/src/boot.rs:1775`, `crates/kid-core/src/boot.rs:1853`.

**RESOLVED candidate — level timer seed now includes Init_SpriteAttr_HUD's `addq #1` pre-decrement second** (`Init_Timer_and_Bonus_Flags` / `Init_SpriteAttr_HUD` / `Decrease_Time_Left` / `loc_C0CC`)
During level load the ASM seeds the timer in two routines. `Init_Timer_and_Bonus_Flags` (kid.asm:6551-6564) sets `Time_Minutes=3` and clears both seconds digits and `Time_Frames` (display 3:00); then `Init_SpriteAttr_HUD` (sub_14244, kid.asm:27087-27101, called at kid.asm:24124 during title-card graphics setup before gameplay is interactive) does `addq.w #1,(Time_Seconds_low_digit)` and `move.w #1,(Time_SubSeconds)`, so the seeded display at gameplay start is 3:01 (181 displayed seconds). Native now models that with `LEVEL_TIMER_START_SECONDS=181` and `sub_frames=1`, while the separate `LEVEL_TIMER_COMPLETION_BASE_SECONDS=180` keeps `loc_C0CC`'s `addi #$B4` completion-time formula on the ROM base. Focused regressions cover the 3:01 seed, the first-tick 3:01→3:00 normalisation, the later 60-frame cadence, and the full countdown expiry frame. Human playtest should still validate the visible HUD/timer-death cadence. Kind: fixed-candidate. `crates/kid-core/src/types.rs`, `crates/kid-core/src/constants.rs`, `crates/kid-core/src/combat.rs`, `crates/kid-core/src/trace.rs`.

### Medium severity

**RESOLVED candidate — Pause entry now consults Allow_Pausing through the level fade-in window** (`loc_74C8` / `loc_74B0` / `Teleport` / `sub_73D0` / `loc_7420`)
ASM `loc_74C8` (kid.asm:7631-7637) gates pause entry on a two-stage check: A-not-held AND `tst.b (Allow_Pausing).w; beq.w loc_7452`. `Allow_Pausing` ($FFFFFB56, variables.asm:122) is BSS-zero at boot, set (`$FF`) only when the per-level fade-in worker `sub_73D0` finishes (`loc_7420`, kid.asm:7561), and cleared (`$00`) on every `Teleport` (kid.asm:14773) — the shared tail for death (lose_life), telepad warp, level-skip-cheat warp, and level-clear advance. Native now carries live `allow_pausing` state, clears it across level-entry/death/warp/skip transitions, sets it after the seventeenth InGame fade refresh, and blocks `handle_start_press` while it is clear. Regression coverage asserts Start is ignored before `Allow_Pausing` and only pauses after the `sub_73D0` completion window. Kind: fixed-candidate. `crates/kid-core/src/boot.rs`, `crates/kid-core/src/lib.rs`, `crates/kid-core/src/level.rs`, `crates/kid-core/src/tests/combat_tests.rs`.

**RESOLVED candidate — CONTINUE? screen consumes a continue only on Start, matching `Ctrl_Held` bit 7** (`loc_D350` / `loc_D3AA` / `Use_Continue` / `Continue_Screen`)
In both ROM continue-countdown wait loops the only input that grabs a continue is Start: `loc_D350` (kid.asm:16530-16531) and `loc_D3AA` (kid.asm:16557-16558) each do `tst.b (Ctrl_Held).w; bmi.s Use_Continue` — `bmi` tests bit 7 of the SACBRLDU button byte (variables.asm:30), i.e. Start only. Native gates the live `ContinueCountdown` use path on `input.start` and has a regression asserting A/B/C alone leave the countdown running. Kind: fixed-candidate. `crates/kid-core/src/boot.rs`, `crates/kid-core/src/tests/movement_tests.rs`.

**RESOLVED candidate — Use_Continue clears extra_hitpoint_slots** (`Use_Continue`)
ASM `Use_Continue` (kid.asm:16563-16575) resets the run — `Number_Lives=3`, `Current_Helmet=0`, `Number_Diamonds=0`, `Number_Hitpoints=2`, and crucially `clr.w (Extra_hitpoint_slots).w` (kid.asm:16572) — then branches directly to `Teleport`, skipping the `lose_life` body, so this is its own clear. Native now clears `progression.extra_hitpoint_slots` in the live `ContinueCountdown` Start path before respawn reset, and `use_continue_clears_extra_hitpoint_slots_loc_d3c4` covers a previously earned Diamond-Power extra-HP slot. Kind: fixed-candidate. `crates/kid-core/src/boot.rs`, `crates/kid-core/src/tests/movement_tests.rs`.

**RESOLVED candidate — Continue countdown includes the `loc_D3AA` second Start window** (`loc_D350` / `loc_D3AA` / `Continue_Screen` / `loc_D3F0`)
The ROM continue screen has two countdown loops that both poll Start for `Use_Continue`: `loc_D350` runs `$123`(291) frames, then (after kicking the text/number objects into the falling fade at `loc_D372`/`loc_D386`) `loc_D3AA` runs another `$EF`(239) frames, each `tst.b (Ctrl_Held); bmi.s Use_Continue`; only after `loc_D3AA` expires does `loc_D3F0` return to title (kid.asm:16526-16560). Regressions assert the old timeout boundary remains in CONTINUE? and Start during the second window spends the continue. Kind: fixed-candidate. `crates/kid-core/src/boot.rs`, `crates/kid-core/src/constants.rs`, `crates/kid-core/src/tests/movement_tests.rs`.

**RESOLVED candidate — Per-player state bank preserves Extra_hitpoint_slots** (`sub_8A4` / `loc_8B4` / `loc_8BA` / `sub_8C2` / `loc_8D2` / `loc_8D8`)
ASM `sub_8A4` (load) and `sub_8C2` (save) copy an 11-word per-player bank (`moveq #$A,d0`, kid.asm:973) between the working region at `Number_Lives` ($FC3E) and `Player_X_Lives` ($FC54 / $FC6A). Kind: fixed-candidate. `crates/kid-core/src/types.rs`, `crates/kid-core/src/level.rs`, `crates/kid-core/src/tests/helmet_tests.rs`, `crates/kid-core/src/tests/level_tests.rs`.

**Options control-scheme remap (Permute_ABCButtons) never applied to live input — schemes 1-5 have no gameplay effect** (`ReadJoypad` / `Permute_ABCButtons` / `sub_CCE` / `loc_CE8`)
The ROM calls `Permute_ABCButtons` inside `ReadJoypad` immediately after each `Joypad_ReadFromHardware` and *before* storing the result (kid.asm:1361-1363 for `Ctrl_1`, 1366-1368 for `Ctrl_2`), so the remap rewrites the very bytes downstream gameplay consumes. The routine (kid.asm:1458-1476) skips demo mode, early-returns on scheme 0, then jumps a five-entry table remapping bits 4/5/6 (B/C/A → Speed/Jump/Special) via `bclr`/`bset`. Native models it faithfully as `with_abc_buttons_permuted` (types.rs:1075) with unit tests, but the helper has zero live callers — the live input store path (lib.rs:1965-1980) and `gameplay_input` (lib.rs:2583) read button fields directly, and `options_controls_scheme` (lib.rs:259) feeds only the options-menu label renderer (boot.rs:4457, scene.rs:1194). TAS/demo parity never catches this because the ASM itself skips the remap in demo mode, so every oracle trace exercises only scheme 0. Found by the wave-2 completeness critic; confirmed by an independent refuter. Kind: helper-unwired. `crates/kid-core/src/types.rs:1075`, `crates/kid-core/src/lib.rs:1965-1980`, `crates/kid-core/src/lib.rs:2583-2606`, `crates/kid-core/src/boot.rs:4457`.

**Options Fast-Action Speed inversion (`not.b Ctrl_A_Held`) never applied — Fast and Normal play identically** (`loc_749C` / `loc_74B0`)
Every player-update frame the ROM tests `Options_Suboption_Speed` ($FFFFFDC9; Normal=0, Fast=-1 per variables.asm:205) and, when Fast Action is selected, executes `not.b (Ctrl_A_Held).w` (kid.asm:7619-7621, demo-mode skipped at 7617-7618), inverting the held run latch so the run modifier becomes hold-to-walk / tap-to-run; downstream `loc_9974` (kid.asm:11509-11516) selects run accel `$20` vs walk accel `$10` from that latch. Native stores `options_speed_button_fast` (lib.rs:261) from the menu and renders its label (boot.rs:4639) but never consumes it in `gameplay_input` or movement; the faithful helper `with_speed_option_a_inverted` (types.rs:1048-1050) is called only from tests (combat_tests.rs:15980-16008). Found by the wave-2 completeness critic; confirmed by an independent refuter. Kind: helper-unwired. `crates/kid-core/src/types.rs:1048`, `crates/kid-core/src/lib.rs:261`, `crates/kid-core/src/lib.rs:2583-2606`, `crates/kid-core/src/boot.rs:4639`.

## Not audited

Scout exclusions and units resolved with no gap:

- **level-timer-decrement-and-freezes** — audited full; no gap. The premise (timer running during transforms / FB4B freezes) does not hold: the live timer is suppressed in all windows the ASM freezes it via lifecycle/transform early-returns (step_lifecycle returns false for Dying/LevelComplete/GameOver → refresh_opening_slice early-returns; `gameplay_hibernating_for_transform()` early-returns during form-change flash) rather than mirrored flag bytes. The unconditional tick is `combat.rs:10908`; the early-return at lib.rs:2920 prevents over-ticking.
- **title-attract-rotation-demo-handoff** — audited full; no gap. The in-scope idle→demo→title cycle and auto-timeout-vs-manual-Start handoff (mode-clear vs paused-title) are faithfully modelled; per-frame oracle constants were explicitly out of scope.
- **demo-input-stream-no-end-guard** — audited full; no gap. The ORIGINAL_QUIRK (six demo-1 overflow bytes read past `Demo_InputData1` into the following art blob before the timeout return) is faithfully reproduced on a live path; the six overflow bytes `[0x06,0xC4,0xC7,0xFF,0x9A,0x14]` were ROM-verified at offset 0x1E6E3, and the timeout edge consumes indices {498..503} only.
- **2P death-handoff survivor dispatch** (`loc_B894` / `loc_B8D0`) — native's Dying handler takes `number_lives==0 → GameOver` before `try_switch_player`, so in 2P a player exhausting their lives ends the game even if the other survives; explicitly marked not-implemented in code (combat.rs:9893) and recorded as a known limitation in `combat-fidelity-audit.md:124`. Not re-reported.
