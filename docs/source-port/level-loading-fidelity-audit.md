# Level-Loading Fidelity Audit

Adversarially-verified audit of the Kid Chameleon source-port's **level-loading** subsystem (`level.rs` and its load-time collaborators `terrain.rs`, `lib.rs`, `weather.rs`, `platforms.rs`, `vdp.rs`), comparing each load-time unit to the `kid.asm` `Load_InGame` / `Load_Level` routines.

The recurring failure mode is the same one the enemy-fidelity audit (`enemy-fidelity-audit.md`, #176) and the dead-helper census (`dead-helper-census.md`, #203) found crate-wide: **ASM-faithful pure helpers exist and are unit-tested, but carry `#[cfg_attr(not(test), allow(dead_code))]` and are never called from the live load path.** Most of `Load_Level`'s tail (block-mapping copy → theme palette → theme art → camera/music) is modelled helper-for-helper and verified against the ROM, yet the live loader (`reload_block_grid_for_level`, `level.rs:17537`, and `begin_level_entry`, `level.rs:17370`) loads only the collision block grid + block list and sets up murder wall and weather. The whole palette/art/background/scroll/music tail is a modelled-but-dead island.

Three findings stand out because they are **not** the simple modelled-but-unwired shape:

- **Architectural — terrain & block-layout decode are delegated to the emulator, not the port.** The live path does not natively decode terrain or the block layout at all. The build-time path runs the real ROM inside the jgenesis emulator (`crates/kidcli/src/inspect.rs:1023` `dump_level_layout`), warps to the level, and reads the finished `Level_Layout` RAM image to `level-layout/<id>.bin`; at runtime `load_block_grid_for_level` (`level.rs:17570`) just slices that dump as 2-byte cells via `terrain::BlockGrid::from_level_layout` (`terrain.rs:356`). So `Decompress_Chunk`, the theme-collision index map, `AddrTbl_BlockTypes` block-type dispatch, the hidden/prize scratch lists, and `LoadBlockLayout` are *correct for any pre-dumped level* but the port has **no independent representation** of any of them — the native decoders are all dead, and there is no native theme-collision index table at all. This is one architectural fact surfacing as several separate "gaps".

- **A genuine correctness bug independent of wiring** — the non-oracle fallback corrupts terrain. When the `.bin` dump is absent, `load_block_grid_for_level` falls back to `load_decoded_block_grid_for_level` (`level.rs:17592`), which feeds the **raw, undecoded** BLOCK resource straight into `BlockGrid::from_level_layout` as if it were final `Level_Layout` words. The block resource is a compressed block-entry run-list, not collision cells, so collision/skin/block-type are derived from garbage. This path is reachable for any level whose oracle warp was skipped (`crates/kidcli/src/main.rs:3369` skips known-broken levels), so those levels load a corrupt grid rather than no grid.

- **`Number_blank_top_rows` is dropped from level height and `Camera_max_Y`, inconsistently.** The ROM reads the header Y byte as `y size + flags`, derives `blank_top_rows = ((y>>6)&3)*2`, and **adds** it to `Level_height_blocks/tiles/pixels` *and* `Camera_max_Y` (`kid.asm:23653-23675`), then `sub_140F6` physically shifts the decoded grid down and fixes up every block-list coordinate. Native `level_bounds` (`level.rs:18436`) computes `height = height_screens*224` with no blank-top extension, and `reload_block_grid_for_level` never shifts the grid — the faithful `blank_top_rows_from_height_flag_bits_sub_140F6` (`terrain.rs:410`) and the eight `adjust_*_for_blank_top_rows_loc_141EE…` helpers (`level.rs:7102-7280`) are test-only. The inconsistency: enemy spawn coords **do** apply the blank-row offset (`enemies.rs:39859`) while terrain/bounds/camera do not, so any level with nonzero top-2 height bits loads terrain and enemies in mismatched rows behind a short camera box.

## Confirmed gaps

### High severity

**Foreground terrain decode — non-oracle fallback misreads the raw BLOCK resource as final `Level_Layout` cells** (`loc_11C10 / loc_11C34 / loc_11C36`)
When the `level-layout/<id>.bin` oracle dump is absent, `load_block_grid_for_level` falls back to `load_decoded_block_grid_for_level` (`level.rs:17592`), which reads `decoded.block.relative_path` (`level.rs:17606`) and feeds it straight into `BlockGrid::from_level_layout` interpreting it as 2-byte-per-cell `Level_Layout` words (`level.rs:17611-17615`). But `decoded.block` is the **raw, undecoded** block-layout resource (`crates/kid-data/src/lib.rs:3887-3954` builds it via `export_raw_level_asset` with no Saxman-decode and no theme-map). In the ROM the block layout is a different structure — a compressed run-list dispatched through `AddrTbl_BlockTypes` (`loc_11C7E`, `kid.asm:23840-23848`) — applied *on top of* the already-built terrain grid, not as the grid itself. So this fallback never runs `Decompress_Chunk`, never applies the theme-collision index that produces each cell's collision nibble, and misinterprets a block-entry stream as raw collision cells; `Cell::from_be_bytes` (`terrain.rs:111`) then derives collision/block_type/skin from garbage. Reachable for any level whose oracle warp was skipped (`crates/kidcli/src/main.rs:3369`).

**Block-type dispatch — entire `AddrTbl_BlockTypes` dispatch unwired; live path uses the emulator RAM dump** (`loc_11C7E / AddrTbl_BlockTypes / loc_122B8 …`)
The ROM (`kid.asm:23839-23848`) walks the decoded block-layout word stream and, per entry, indexes `AddrTbl_BlockTypes` by `block-type*4` and jsr's the handler, writing special block cells (smash/ice/rubber/steel/mushroom/shooter) and queueing prize/ghost/hidden scratch entries. Native models this faithfully — `block_layout_dispatch_words_loc_11C7E` (`level.rs:4141`), `block_type_base_cell_loc_122B8` (`level.rs:4154`), and the whole `loc_122C0/122DA/122F6/123DC/124A6/1253A` family — but every one is `#[cfg_attr(not(test), allow(dead_code))]` with callers only in `crates/kid-core/src/tests/`. The live runtime instead loads a pre-baked `Level_Layout` RAM dump (`inspect.rs:1023`) and parses it raw via `terrain::BlockGrid::from_level_layout` (`terrain.rs:356`), which does no block-type dispatch. The port has no native implementation of this subsystem on the live path.

**Block layout — `L_Forced_Entry` steel-block hardcode never implemented** (`loc_11C7E` preamble, `kid.asm:23835-23837`)
The ROM checks `Current_LevelID == L_Forced_Entry` and, if so, hardcodes a steel block (`$E50B → $FFBCEA`, cell `($20,$B)`) before the dispatch loop. No native Rust references `L_Forced_Entry` or this write on any path — grep for `Forced_Entry`/`L_Forced` across non-test `crates/**/*.rs` finds nothing, and `kid-data` has no such handling. The steel block only reaches the loaded level because the emulator runs the real ROM during `dump_level_layout` (`inspect.rs:1023`); a native-only reimplementation would silently omit it.

**Block layout — hidden/prize scratch-list build (`loc_11C96/loc_11CA8`) and FG-queue overflow guards never wired** (`loc_11C96 / loc_11CA8 / loc_11CB6 / loc_11CCA / loc_11CE0`)
After dispatch, the ROM copies the temp hidden-block list (`$FFFF0280`) into the final block-list buffer (`kid.asm:23851-23861`), then runs overflow guards comparing the prize/hidden/ghost spans against `FGPlane_UpdateQueueCustom=$43BC`, hanging on overflow (`kid.asm:23868-23905`). Native models `hidden_block_copy_setup_loc_11C96` (`level.rs:4780`), `copy_hidden_block_entries_loc_11CA8` (`level.rs:4801`), `prize_block_list_guard_loc_11CB6` (`level.rs:4826`), `hidden_block_list_guard_loc_11CCA` (`level.rs:4839`) — all dead, test-only. The live runtime reads the already-built Block List from emulator work-RAM (`BLOCK_LIST_ADDR`, `inspect.rs:1146`) via `terrain::BlockList::from_raw`, so the native scratch-list construction and the `$43BC` guard logic are entirely dead.

**Theme palette load — FG theme palette copy (`loc_11DB0`) modelled but never wired** (`loc_11D8E / loc_11D9E / loc_11DAC / loc_11DB0`)
The ROM (`kid.asm:23931-23983`) dereferences `LnkTo_ThemePal1_Index` by theme index and copies 15 words into `Palette_Buffer+$2`. Native models the override classification (`level.rs:7855`) and the final copy (`copy_foreground_palette_loc_11DB0`, `level.rs:7916` → `palette_buffer[1..=15]`) faithfully, but every fn is `allow(dead_code)`, invoked only from `tests.rs:227-231`. No live load path resolves `LnkTo_ThemePal1_Index` or populates a runtime in-game `Palette_Buffer`. Loaded level state lacks the foreground theme palette entirely.

**Theme palette load — BG theme palette copy (`loc_11E16`) modelled but never wired** (`loc_11DF4 / loc_11DF8 / loc_11E04 / loc_11E12 / loc_11E16`)
The ROM (`kid.asm:23985-24036`) dereferences `LnkTo_ThemePal2_Index` by `Background_theme`, writes word 0 to `Palette_Buffer` and copies 7 words into `Palette_Buffer+$32`. Native models classification (`level.rs:7935`) and the copy (`copy_background_palette_loc_11E16`, `level.rs:8026`) faithfully, but all are dead, called only from `tests.rs:152-153,227-231`. No live path resolves `Background_theme`/`LnkTo_ThemePal2_Index` or writes the BG palette into a runtime buffer.

**Theme palette load — per-map override palette DATA absent from native** (`Pal_12CBC / Pal_12CDA / Pal_12CF8 / Pal_12D26 / Pal_12D54`)
The ROM substitutes hardcoded override palettes for specific maps (Plethora → `Pal_12CBC`; Stairway/Elsewhere23 cave FG → `Pal_12CDA`; Crypt/Alien-Twilight FG → `Pal_12D26`; BG cave → `Pal_12CF8`; BG alien → `Pal_12D54`). Native's `apply_*` override helpers (`level.rs:7898,8011`) take the override palette as a `u16` parameter, but **no native data table holds these ROM palette words** — `Pal_12CBC/12CDA/12CF8/12D26/12D54` appear only inside doc comments (`level.rs:7904,7939,8017`). Even if the classifiers were wired, there is no source of the override colours; the cave/Plethora/Crypt/Alien-Twilight levels could not receive their distinct palettes.

**Theme art/tileset load — FG/BG art VRAM decompress + palette permutation entirely dead** (`loc_11E48 … loc_11EFA`)
During level load the ROM (`kid.asm:24038-24117`) decompresses FG theme art (base `$1780`) selecting the City/Forest/Mountain permutation table, then BG theme art (base `$F000`) selecting Forest/Mountain/Hill permutations. Native models every step as ASM-faithful helpers — `select_foreground_art_permutation_loc_11E48` (`level.rs:8160`), `…_loc_11E54` (`8178`), `select_background_art_permutation_loc_11E8A` (`8196`), `prepare_background_art_decompress_loc_11EA2` (`8233`), `prepare_foreground_art_decompress_loc_11E60` (`8334`), `shared_vram_art_decompresses_loc_11EFA` (`8309`) — but NONE are called from any live path, and the underlying decompress engine (`level.rs:2153,2382,3010`) likewise has zero non-test callers. The live load (`reload_block_grid_for_level`, `level.rs:17537`) loads only the collision grid + block list; it never decompresses theme art or applies a permutation for gameplay levels.

**Theme art/tileset load — Hill alt background art (second BG decompress) modelled but never executed** (`loc_11EA2 / loc_11EC4`)
When `Background_theme==Hills` the ROM runs a *second* `DecompressToRAM` using `Palette_Permutation_BGHill_alt` and `ThemeArtBack_HillAlt` (base `$F800`), layering Hill alt tiles on the base BG art (`kid.asm:24081-24087`). Native models the base Hill permutation (`prepare_background_art_decompress_loc_11EA2`, `level.rs:8233`) but provides **no helper for the Hill-alt second decompress at all** (`prepare_mountain_background_art_loc_11EC4`, `level.rs:8247`, covers only the Mountain branch). Hill levels would be missing their alternate-tile BG art.

**Theme art/tileset load — Mountain cave/lightning weather BG variant modelled but never executed** (`loc_11EC4 / loc_11EEA / loc_11EF2`)
Mountain backgrounds run a second `DecompressToRAM` at base `$FCA0` (`ThemeArtBack_CaveAlt`); if `Level_Special_Effects` is `WeatherID_Storm(2)`/`Storm_and_Hail(3)` the source is swapped to `ThemeArtBack_MountainLightning` (`kid.asm:24089-24106`). Native faithfully models `prepare_mountain_background_art_loc_11EC4` (`level.rs:8247`), `apply_mountain_weather_override_loc_11EEA` (`8266`), `prepare_followup_background_art_decompress_loc_11EF2` (`8293`) — constants verified against `constants.asm` — but all three are test-only; the live load never invokes them, so Mountain cave art and the storm-lightning variant are absent.

**Block-mapping build — post-decode pointer cursor (`level_load_pointers_loc_11D0C`) dead; theme-mapping/enemy-layout pointer setup unwired** (`loc_11D0C`)
`loc_11D0C` consumes the `a0` cursor: reads the background-tiles pointer, stores the theme mappings addr into `Addr_ThemeMappings`, and splits the enemy-layout pointer into `Addr_EnemyLayout`/`Addr_EnemyLayoutHeader` (`kid.asm:23908-23915`). Native `level_load_pointers_loc_11D0C` (`level.rs:7285`) models this faithfully but is `allow(dead_code)` with the sole caller in `helmet_tests.rs:2704`. Because this cursor consumer is unwired alongside the copy loop, the whole `loc_11D0C..loc_11D46` segment is a modelled-but-dead island.

**Enemy spawn — `loc_11D0C` enemy-layout pointer install dead; live load uses a parallel re-decode** (`loc_11D0C`)
The ROM installs the live enemy-layout cursor and header pointer (`Addr_EnemyLayout`/`Addr_EnemyLayoutHeader`) that the whole spawn-walk subsystem keys off. The faithful `level_load_pointers_loc_11D0C` (`level.rs:7285`) reproduces this but is dead (only `helmet_tests.rs:2704`). The live load never installs the pair; instead `kid-data/src/lib.rs:1204` `parse_enemy_layout` re-decodes the raw asset into a `kid_data::EnemyLayout`, surfaced via `NativeRuntime::enemy_layout` (`level.rs:18398`).

**Enemy spawn — `loc_31F8E` reset+seek (status-table seed, header-threshold walk, art/palette) entirely unwired** (`loc_31F8E / loc_31FCE / loc_31FD4 / loc_31FE6 / loc_3200A / loc_3204E`)
The ROM's load-time anchoring (`kid.asm:37368-37445`) clears 30 words of `EnemyStatus_Table`, seeds the seek axis from the header, runs the `loc_31FD4` count-skip seek (advancing `a1` by `count<<3` per skipped record), re-anchors on the matched record, seeds `EnemyStatus_Table` from each object's status byte (`$C000|unk_3680C[slot]` respawn-timing words), and calls `Load_EnemyArtPaletteToVRAM`. The faithful helpers all exist — `enemy_layout_reset_and_seek_loc_31F8E` (`level.rs:7312`), `enemy_layout_status_word_loc_3200A` (`7534`), `enemy_layout_finish_loc_3204E` (`7577`) — all dead, referenced only from `level_tests.rs`. The live path never seeds `EnemyStatus_Table` from the layout (only `.fill(0)`, `enemies.rs:39946`); `enemy_layout_view` (`enemies.rs:39083`) is a generic unsigned bounds scan, not the signed `blt` count-skip seek.

**Enemy spawn — `Manage_EnemyLoading` per-frame streaming spawn walk dead; live uses a generic activation window** (`loc_3682C / loc_36840 / loc_3685E / loc_368A6 / loc_36900 / loc_3691E`)
The ROM streams objects in as the camera advances via an `EnemyStatus_Table` countdown/respawn state machine (`kid.asm` ~37969-38098): per entry it branches on the status word (0=spawn, `$FFFF`=skip, bit13=countdown-active, bit14-clear=force-reload, else countdown-reload) and on spawn allocates the slot, packs `(d6-d7-1)|$C0/$80` into `$42(a0)`, and writes `$FFFF` back. Faithful helpers for every branch exist — `manage_enemy_loading_setup_loc_3682C` (`level.rs:7383`), `…_status_branch_loc_36840` (`7413`), `…_count_down_active_loc_3685E` (`7444`), `…_spawn_object_loc_3691E` (`7498`) — all dead, referenced only from `helmet_tests.rs`. The live runtime runs `activate_enemies_with_rng` (`enemies.rs:9091`), a generic `window.contains(x,y)` scan with invented activation-window constants (`ACTIVATION_WINDOW_X_LEAD=0x1C0` etc., `constants.rs:460-462`) plus a `killed` HashSet, none of which corresponds to the ROM state machine.

**Enemy spawn — multi-record layouts collapsed to a single segment; `loc_31FD4` count-skip seek unmodeled** (`loc_31FD4 / loc_31FE6`)
The ROM enemy layout is a sequence of header records, each with its own threshold, art slots, and object batch; `loc_31FD4` seeks across them by camera position and re-anchors on the active record (`kid.asm:37391-37412`), so different parts of a level expose different batches/art. Native `parse_enemy_layout` (`kid-data/src/lib.rs:1204`) reads exactly **one** header + one batch and emits `segments: vec![segment]` (`lib.rs:1264`); nothing pushes additional segments. Although `enemy_layout_view` (`enemies.rs:39083`) is written to iterate multiple segments, the parser never supplies more than one, so the live path silently drops every record after the first and never streams later batches/art as the camera advances.

**Background scroll — BG dimensions/format/theme load-time setup entirely unwired** (`loc_11B40 / loc_11B9A / loc_11BCC`)
The ROM computes `Background_width=(tiles>>2)+$1E`, `Background_height=(tiles>>2)+$15`, decodes the BG-theme byte into `Level_Special_Effects` (upper nibble) and `Background_theme` (lower nibble), then at `loc_11BCC` sets `Background_format` and forces `Background_width=$40` for layered (type2) themes (`kid.asm:23728-23775`). Native models all of this in `background_dimensions_loc_11B40` (`level.rs:7729`) and `decode_background_theme_flags_loc_11B9A` (`level.rs:7783`), but both are dead. The live loader sets **no** background width/height/format/theme/special-effects state — there is no persistent background/scroll field in the runtime struct at all. Loaded level state lacks BG dimensions, format and theme entirely.

**Background scroll — `off_7B1EC` scroll-speed list never wired (dead per-frame parallax)** (`loc_3050A BackgroundScroll_ComputeShiftLayers / off_7B1EC`)
Each frame the ROM dereferences `LnkTo_BackgroundScroll_Index` (`off_7B1EC`) indexed by `MapOrder_Index[Current_LevelID]`, walks the `$FF`-terminated per-8px-row speed bytes through the `Horiz_Scroll_Data` shift LUT, negates and fills the 224-entry `Horiz_Scroll_Buffer`, then dispatches Forest/Desert ripples (`kid.asm:34172-34253`). Native models the consumer faithfully — `background_scroll_shift_layers_setup_loc_3050A` (`level.rs:13444`), the fill family, `background_scroll_theme_dispatch_loc_30598` (`13543`), the ripple helpers — every one `allow(dead_code)` with ZERO callers in `lib.rs`/`scenario.rs`. `step_frame` produces no in-game `Horiz_Scroll_Buffer`/VSRAM-HScroll output, so auto-scroll and parallax are entirely absent from gameplay.

**Background scroll — per-frame shift-data compute + VSRAM transfer dead; no scroll output** (`loc_2FFE8 / loc_300BA / loc_30452`)
The ROM's per-frame chain seeds `Horiz_Scroll_Data` phase from `Background_width`/`Camera_X`/`Time_Frames`, then DMAs `Horiz_Scroll_Buffer` to VRAM `$1400` and sets VSRAM, gated on `Background_NoScrollFlag` and `Background_format` (`kid.asm:33642-34070`). Native models `background_scroll_upper_pass_loc_2FFE8` (`level.rs:12411`), `transfer_scroll_data_vsram_setup_loc_300BA` (`12543`), and the `reduce_background_scroll_phase`/`sub_304B4` family (`13332`) — all dead, test-only. The live runtime never DMAs a scroll buffer during gameplay; even the initial title/boot `Horiz_Scroll_Buffer` seed (`vdp.rs:2459-2465`) is never updated in-game.

### Medium severity

**Load_InGame — blank-top-rows grid shift (`sub_140F6`) unwired; dimensions/camera omit the top-2-bit height extension** (`loc_11FD2 → sub_140F6 / loc_141EE / loc_141C8`)
The ROM derives `Number_blank_top_rows = height_flag_bits*2`, adds it to `Level_height_*` and `Camera_max_Y`, then `sub_140F6` shifts the decoded grid down, blank-fills the new top rows, and fixes up every block-list/hidden-block coordinate (`kid.asm:23654-23675, 26995-27081`). Native `level_bounds` (`level.rs:18436`) computes `height = height_screens*224` with no extension, the camera clamp (`lib.rs:2437`, `blocks.rs:3633`) is short by `blank_top_rows*16`px, and `reload_block_grid_for_level` never shifts the grid. Faithful helpers `blank_top_rows_from_height_flag_bits_sub_140F6` (`terrain.rs:410`) and the eight `adjust_*_for_blank_top_rows_loc_141EE…` (`level.rs:7102-7280`) are test-only; `header.height_flag_bits` (`kid-data/src/lib.rs:1192`) is parsed but read by nothing except `trace.rs`. Any level with nonzero top-2 height bits loads terrain in the wrong rows behind an undersized camera. *(See the intro for the enemy-vs-terrain inconsistency.)*

**Load_InGame — Forced Entry steel-block special-case (`loc_11C7E`) not modelled** (`loc_11C72 / loc_11C7E`)
After `LoadBlockLayout` the ROM hard-inserts a steel block (`$E50B → $FFBCEA`, cell `($20,$B)`) for `L_Forced_Entry` before the dispatch loop (`kid.asm:23835-23838`). Native `reload_block_grid_for_level`/`load_block_grid_for_level` (`level.rs:17537/17570`) build the grid from the layout file with no Forced-Entry override; the `block_layout_dispatch_words_loc_11C7E` helper (`level.rs:4141`) models the dispatch walk but is test-only and performs no steel-block insert. *(Same root as the high-severity "steel-block hardcode never implemented"; this row tracks the orchestrator's missing special-case branch.)*

**Load_InGame — level BGM selection (`loc_11FC8/loc_12004`) never invoked on the live load path** (`loc_11FC8 / loc_11FD2 / loc_12004`)
The ROM ends `Load_InGame` by playing level music: `bgm_Murderwall` if `MurderWall_flag`, else `unk_1201E[Foreground_theme]` (`kid.asm:24170-24197`). Native models the table lookup (`select_foreground_theme_music_loc_12004`, `level.rs:8438`) and the murderwall/theme selector (`8418-8431`), but these are called only from `helmet_tests.rs`. The live orchestrator (`begin_level_entry`, `level.rs:17370`) wires block grid, murder wall and weather but never selects or queues level music — likely an architectural scope decision (no level-BGM audio consumer), but the ROM-ordered final music step is absent.

**Level header decode — blank-top-rows never added to level height / `Camera_max_Y`** (`loc_11AE4`)
`kid.asm:23653-23675` adds `Number_blank_top_rows = ((y>>6)&3)*2` back into `Level_height_*` and `Camera_max_Y_pos`. The native live path never performs this addition: `level_bounds()` (`level.rs:18443`) returns `height_pixels = height_screens*224` with `height_screens = raw_height & 0x3F`, and the camera Y maximum is `height_pixels - VIEWPORT_HEIGHT` (`level.rs:17787`). **Level header decode — `$FFFFFC29` continue-flag player-start skip not modelled** (`loc_11BD2 / loc_11BE4 / loc_11BEC`)
