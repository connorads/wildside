# Level-Loading Fidelity Audit

Adversarially-verified audit of the Kid Chameleon source-port's **level-loading** subsystem (`level.rs` and its load-time collaborators `terrain.rs`, `lib.rs`, `weather.rs`, `platforms.rs`, `vdp.rs`), comparing each load-time unit to the `kid.asm` `Load_InGame` / `Load_Level` routines.

The recurring failure mode is the same one the enemy-fidelity audit (`enemy-fidelity-audit.md`, #176) and the dead-helper census (`dead-helper-census.md`, #203) found crate-wide: **ASM-faithful pure helpers exist and are unit-tested, but carry `#[cfg_attr(not(test), allow(dead_code))]` and are never called from the live load path.** Most of `Load_Level`'s tail (block-mapping copy → theme palette → theme art → camera/music) is modelled helper-for-helper and verified against the ROM, yet the live loader (`reload_block_grid_for_level`, `level.rs:17537`, and `begin_level_entry`, `level.rs:17370`) loads only the collision block grid + block list and sets up murder wall and weather. The whole palette/art/background/scroll/music tail is a modelled-but-dead island.

Three original findings stood out because they were **not** the simple modelled-but-unwired shape:

- **RESOLVED 2026-06-13 — terrain & block-layout decode are no longer delegated only to the emulator.** Fixtured levels still prefer the oracle-dumped `level-layout/<id>.bin`, but `NativeRuntime::decode_level_layout` now implements ASM `loc_11C10`/`loc_11C34`/`loc_11C36` terrain decode, the `L_Forced_Entry` steel insert, and the `loc_11C7E` block-overlay pass as the fixture-missing fallback. Verification on current HEAD: `load_block_grid_refuses_raw_decoded_block_resource_for_mapped_level`, `load_block_grid_for_level_falls_back_to_native_decoder`, and `decode_level_layout_matches_fixture_collision_cells_loc_11c34` pass; the byte comparison reports 418386 exact cells and only 214 explained runtime-toggled overlay residuals. The remaining architecture debt is narrower: normal fixtured levels still consume the oracle dump first, and native block-list scratch/overflow guard construction remains separate from the generated block-list path.

- **RESOLVED 2026-06-13 — the non-oracle fallback no longer corrupts terrain.** The old raw-BLOCK-as-`Level_Layout` path has been replaced by the native terrain decoder described above, and guard coverage proves raw `decoded.block` assets fail closed instead of becoming collision cells.

- **RESOLVED 2026-06-15 — `Number_blank_top_rows` now extends generated level height and shifts loaded grids.** The ROM reads the header Y byte as `y size + flags`, derives `blank_top_rows = ((y>>6)&3)*2`, and adds it to `Level_height_blocks/tiles/pixels` and `Camera_max_Y` (`kid.asm:23653-23675`), then `sub_140F6` physically shifts the decoded grid down and fixes up every block-list coordinate. Native `decode_level_layout` now adds `blank_top_rows_from_height_flag_bits_sub_140F6` to decoded `height_blocks`, `reload_block_grid_for_level` detects unshifted fixture grids and applies `with_blank_top_rows_sub_140F6`, and `level_bounds` includes the extra rows in `height_pixels`. Verified on current HEAD by `load_leveldata_height_flags_extend_level_bounds_loc_15a0` and cache-backed `generated_hell_level_layout_applies_blank_top_rows_sub_140f6`.

## Confirmed gaps

### High severity

**RESOLVED 2026-06-13 — foreground terrain decode fallback no longer misreads the raw BLOCK resource as final `Level_Layout` cells** (`loc_11C10 / loc_11C34 / loc_11C36`)
The old `load_decoded_block_grid_for_level` corruption path is gone. Current `load_block_grid_for_level` falls back to `decode_level_layout`, which reads the decoded foreground skin buffer, builds collision cells from the contiguous ROM theme-collision table (`loc_11C34`/`loc_11C36`), applies the Forced Entry steel insert, and overlays decoded block-layout words through `apply_block_overlay_loc_11C7E`. A guard regression, `load_block_grid_refuses_raw_decoded_block_resource_for_mapped_level`, proves a raw `decoded.block` file is not accepted as `Level_Layout` cells; cache-backed `load_block_grid_for_level_falls_back_to_native_decoder` proves fixture-less bonus levels load through the decoder; cache-backed `decode_level_layout_matches_fixture_collision_cells_loc_11c34` compares the native decoder against generated oracle fixtures.

**PARTIAL 2026-06-13 — `AddrTbl_BlockTypes` dispatch is wired for native-decoded fallback grids, while fixtured levels still prefer the emulator RAM dump** (`loc_11C7E / AddrTbl_BlockTypes / loc_122B8 …`)
The ROM (`kid.asm:23839-23848`) walks the decoded block-layout word stream and, per entry, indexes `AddrTbl_BlockTypes` by `block-type*4` and jsr's the handler, writing special block cells (smash/ice/rubber/steel/mushroom/shooter) and queueing prize/ghost/hidden scratch entries. Current native `decode_level_layout` decodes the block-layout stream and calls `apply_block_overlay_loc_11C7E`, covering all 17 handler shapes for fixture-missing levels. The residual is architectural: ordinary generated levels still prefer pre-baked `level-layout/<id>.bin` dumps, and scratch-list/overflow-guard construction remains separate from the generated `BlockList`.

**RESOLVED 2026-06-13 — `L_Forced_Entry` steel-block hardcode is implemented in the native fallback** (`loc_11C7E` preamble, `kid.asm:23835-23837`)
`decode_level_layout` checks logical level `$21` and inserts cell `$E50B` at `($20,$B)` before the block-overlay pass, matching ASM `loc_11C34` tail. Fixtured levels still receive the same cell from the oracle dump; fixture-less/native-decoded paths now do too.

**Block layout — hidden/prize scratch-list build (`loc_11C96/loc_11CA8`) and FG-queue overflow guards never wired** (`loc_11C96 / loc_11CA8 / loc_11CB6 / loc_11CCA / loc_11CE0`)
After dispatch, the ROM copies the temp hidden-block list (`$FFFF0280`) into the final block-list buffer (`kid.asm:23851-23861`), then runs overflow guards comparing the prize/hidden/ghost spans against `FGPlane_UpdateQueueCustom=$43BC`, hanging on overflow (`kid.asm:23868-23905`). Native models `hidden_block_copy_setup_loc_11C96` (`level.rs:4780`), `copy_hidden_block_entries_loc_11CA8` (`level.rs:4801`), `prize_block_list_guard_loc_11CB6` (`level.rs:4826`), `hidden_block_list_guard_loc_11CCA` (`level.rs:4839`) — all dead, test-only. The live runtime reads the already-built Block List from emulator work-RAM (`BLOCK_LIST_ADDR`, `inspect.rs:1146`) via `terrain::BlockList::from_raw`, so the native scratch-list construction and the `$43BC` guard logic are entirely dead.

**Theme palette load — per-map override palette DATA absent from native** (`Pal_12CBC / Pal_12CDA / Pal_12CF8 / Pal_12D26 / Pal_12D54`)
The ROM substitutes hardcoded override palettes for specific maps (Plethora → `Pal_12CBC`; Stairway/Elsewhere23 cave FG → `Pal_12CDA`; Crypt/Alien-Twilight FG → `Pal_12D26`; BG cave → `Pal_12CF8`; BG alien → `Pal_12D54`). **Theme art/tileset load — FG/BG art VRAM decompress + palette permutation entirely dead** (`loc_11E48 … loc_11EFA`)
During level load the ROM (`kid.asm:24038-24117`) decompresses FG theme art (base `$1780`) selecting the City/Forest/Mountain permutation table, then BG theme art (base `$F000`) selecting Forest/Mountain/Hill permutations. Native models every step as ASM-faithful helpers — `select_foreground_art_permutation_loc_11E48` (`level.rs:8160`), `…_loc_11E54` (`8178`), `select_background_art_permutation_loc_11E8A` (`8196`), `prepare_background_art_decompress_loc_11EA2` (`8233`), `prepare_foreground_art_decompress_loc_11E60` (`8334`), `shared_vram_art_decompresses_loc_11EFA` (`8309`) — but NONE are called from any live path, and the underlying decompress engine (`level.rs:2153,2382,3010`) likewise has zero non-test callers. The live load (`reload_block_grid_for_level`, `level.rs:17537`) loads only the collision grid + block list; it never decompresses theme art or applies a permutation for gameplay levels.

**Theme art/tileset load — Hill alt background art (second BG decompress) modelled but never executed** (`loc_11EA2 / loc_11EC4`)
When `Background_theme==Hills` the ROM runs a *second* `DecompressToRAM` using `Palette_Permutation_BGHill_alt` and `ThemeArtBack_HillAlt` (base `$F800`), layering Hill alt tiles on the base BG art (`kid.asm:24081-24087`). Hill levels would be missing their alternate-tile BG art.

**Theme art/tileset load — Mountain cave/lightning weather BG variant modelled but never executed** (`loc_11EC4 / loc_11EEA / loc_11EF2`)
Mountain backgrounds run a second `DecompressToRAM` at base `$FCA0` (`ThemeArtBack_CaveAlt`); if `Level_Special_Effects` is `WeatherID_Storm(2)`/`Storm_and_Hail(3)` the source is swapped to `ThemeArtBack_MountainLightning` (`kid.asm:24089-24106`). **Block-mapping build — post-decode pointer cursor (`level_load_pointers_loc_11D0C`) dead; theme-mapping/enemy-layout pointer setup unwired** (`loc_11D0C`)
`loc_11D0C` consumes the `a0` cursor: reads the background-tiles pointer, stores the theme mappings addr into `Addr_ThemeMappings`, and splits the enemy-layout pointer into `Addr_EnemyLayout`/`Addr_EnemyLayoutHeader` (`kid.asm:23908-23915`). Because this cursor consumer is unwired alongside the copy loop, the whole `loc_11D0C..loc_11D46` segment is a modelled-but-dead island.

**Enemy spawn — `loc_11D0C` enemy-layout pointer install dead; live load uses a parallel re-decode** (`loc_11D0C`)
The ROM installs the live enemy-layout cursor and header pointer (`Addr_EnemyLayout`/`Addr_EnemyLayoutHeader`) that the whole spawn-walk subsystem keys off. The faithful `level_load_pointers_loc_11D0C` (`level.rs:7285`) reproduces this but is dead (only `helmet_tests.rs:2704`). **Enemy spawn — `loc_31F8E` reset+seek (status-table seed, header-threshold walk, art/palette) entirely unwired** (`loc_31F8E / loc_31FCE / loc_31FD4 / loc_31FE6 / loc_3200A / loc_3204E`)
The ROM's load-time anchoring (`kid.asm:37368-37445`) clears 30 words of `EnemyStatus_Table`, seeds the seek axis from the header, runs the `loc_31FD4` count-skip seek (advancing `a1` by `count<<3` per skipped record), re-anchors on the matched record, seeds `EnemyStatus_Table` from each object's status byte (`$C000|unk_3680C[slot]` respawn-timing words), and calls `Load_EnemyArtPaletteToVRAM`. The faithful helpers all exist — `enemy_layout_reset_and_seek_loc_31F8E` (`level.rs:7312`), `enemy_layout_status_word_loc_3200A` (`7534`), `enemy_layout_finish_loc_3204E` (`7577`) — all dead, referenced only from `level_tests.rs`. **Enemy spawn — `Manage_EnemyLoading` per-frame streaming spawn walk dead; live uses a generic activation window** (`loc_3682C / loc_36840 / loc_3685E / loc_368A6 / loc_36900 / loc_3691E`)
The ROM streams objects in as the camera advances via an `EnemyStatus_Table` countdown/respawn state machine (`kid.asm` ~37969-38098): per entry it branches on the status word (0=spawn, `$FFFF`=skip, bit13=countdown-active, bit14-clear=force-reload, else countdown-reload) and on spawn allocates the slot, packs `(d6-d7-1)|$C0/$80` into `$42(a0)`, and writes `$FFFF` back. Faithful helpers for every branch exist — `manage_enemy_loading_setup_loc_3682C` (`level.rs:7383`), `…_status_branch_loc_36840` (`7413`), `…_count_down_active_loc_3685E` (`7444`), `…_spawn_object_loc_3691E` (`7498`) — all dead, referenced only from `helmet_tests.rs`. The live runtime runs `activate_enemies_with_rng` (`enemies.rs:9091`), a generic `window.contains(x,y)` scan with invented activation-window constants (`ACTIVATION_WINDOW_X_LEAD=0x1C0` etc., `constants.rs:460-462`) plus a `killed` HashSet, none of which corresponds to the ROM state machine.

**Enemy spawn — multi-record layouts collapsed to a single segment; `loc_31FD4` count-skip seek unmodeled** (`loc_31FD4 / loc_31FE6`)
The ROM enemy layout is a sequence of header records, each with its own threshold, art slots, and object batch; `loc_31FD4` seeks across them by camera position and re-anchors on the active record (`kid.asm:37391-37412`), so different parts of a level expose different batches/art. Native `parse_enemy_layout` (`kid-data/src/lib.rs:1204`) reads exactly **one** header + one batch and emits `segments: vec![segment]` (`lib.rs:1264`); nothing pushes additional segments. Although `enemy_layout_view` (`enemies.rs:39083`) is written to iterate multiple segments, the parser never supplies more than one, so the live path silently drops every record after the first and never streams later batches/art as the camera advances.

The live loader sets **no** background width/height/format/theme/special-effects state — there is no persistent background/scroll field in the runtime struct at all. Loaded level state lacks BG dimensions, format and theme entirely.

**Background scroll — per-frame shift-data compute + VSRAM transfer dead; no scroll output** (`loc_2FFE8 / loc_300BA / loc_30452`)
The ROM's per-frame chain seeds `Horiz_Scroll_Data` phase from `Background_width`/`Camera_X`/`Time_Frames`, then DMAs `Horiz_Scroll_Buffer` to VRAM `$1400` and sets VSRAM, gated on `Background_NoScrollFlag` and `Background_format` (`kid.asm:33642-34070`). The live runtime never DMAs a scroll buffer during gameplay; even the initial title/boot `Horiz_Scroll_Buffer` seed (`vdp.rs:2459-2465`) is never updated in-game.
